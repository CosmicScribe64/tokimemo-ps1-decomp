# T-16000 MAIN compilation repairs

All thirteen formerly failing MAIN scopes compile as complete translation units with project IDO 5.3 in Docker. These are NON_MATCHING research drafts, with no production source/header replacement and no byte-match claim. Each result records the resolved instruction-row difference score, SHA-256 hashes, scope, source path and archive path. Compilation is evidence of usable C, not proof of runtime correctness or original author intent.

Run `python3 tools/main_draft_repairs.py` inside the project Docker image to replay serial compilation and scoring. Frozen `baseline-source.c` plus `body.c`, `declarations.h`, and optional `preamble.c` reproduce each `context.c`; `full-context.c` retains the compiler's preprocessed input. `diagnostics.txt` preserves complete command output without the historical last-twelve-lines truncation. Initial census artifacts under `drafts/T-14500/main` remain immutable. Intermediate root inputs are retained under `attempts/before-layout-repair`. The reconstruction scripts record the ordered, one-time transformations, rather than an idempotent alternative harness.

Repairs remove duplicate case 32 (already case 0x20), reconstruct short/word stack arrays, use byte views for GameState offsets and menu buffers, and prepend void prototypes before earlier implicit calls for four functions. The movie function uses observed 20/92/24-byte display/draw/file buffers because repository headers do not define those SDK structures; accesses retain observed offsets and the three-byte file-position store. These archive-only byte buffers do not introduce substitute SDK typedefs into production.

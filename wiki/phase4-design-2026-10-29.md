# Phase 4 design (2026-10-29)

Judged merged plans from the phase4-design workflow (two proposals per area, one judge). Defaults chosen while the user was away are revisable. Implementation tickets: [[tickets/T-30001-modern-widescreen]], [[tickets/T-30002-modern-settings]], [[tickets/T-39016-generic-text-layer]], [[tickets/T-39004-english-asset-completion]].

## Widescreen

Rationale: Both proposals keep native fidelity by keeping the native 320x240 producers untouched. They differ in how they fill the wings and where English text goes. Code checks favour P2 on the wings: hud_compositor fills the whole frame with the checker tile before blitting the room at (0,72), so Class A wings can be source-derived. They also correct the shared Class A y-range error, which is y=72..159, not 24..111. P1 is better on text: a window-space overlay leaves the fidelity Image untouched by construction, while P2's Tier 2 moves native primitives and breaks centre byte identity. Both proposals correctly note that settings_runtime's content_scale_aspect writes do nothing (or misalign content) because the boots zero content_scale_size and use three duplicated fits; one host fixes that. Keeping the existing [original, wide, auto] enum avoids a migration while T-30002 is still in progress. The boot integration and hud_compositor packages touch files with uncommitted core-port edits, so they are serialized last and the rest of the work stays file-disjoint. The user is away, so defaults keep current behaviour and every enhancement is an opt-in pref that can be reverted.

### Plan

- Verdict: both proposals agree on the main rule. The native producers (presenter.render, hud_compositor.render, prologue_text_presenter, NativeCanvas) keep emitting the same 320x240 Image, widescreen is presentation-only, and the T-30001/phase4 idea of a 426x240 logical canvas that the game draws into is rejected. Proposal 2 has the better source evidence: Class A wings can continue the seasonal checker tile. Proposal 1 has the better English-text design: a window-space modern text box instead of reflowing native primitives. The merged plan uses P2's frame composer and checker wings with P1's window-space aperture and text overlay. It drops P2's Tier 2 'Wide Layout', which moves native HUD and dialogue primitives, and P1's derived 'ambient' blur. Both are deferred and need the user's approval.
- Claims verified in code. (1) There are three duplicated fits. first_arrival_boot.gd:165-173 does a min-fit and floors when filter=integer. new_game_entry_boot.gd:173-180 has the same math. playable_boot.gd:461-468 uses a fixed canvas.scale=2 on a 640x480 ColorRect backdrop. (2) first_arrival_boot:55 and new_game_entry_boot:119 set content_scale_size=ZERO. Yet settings_runtime.gd:67-71 maps aspect to content_scale_aspect KEEP/KEEP_HEIGHT/EXPAND and sets stretch INTEGER/FRACTIONAL. That pref does nothing in those boots, and under playable_boot's canvas_items 640x480 base (project.godot) 'wide' would leave the canvas left-aligned. The settings menu exposes it at settings_menu.gd:53. (3) hud_compositor.render fills the frame with _draw_checkerboard (lines 199 and 285; uv, season and fade setters at 34-39), then blits the 320x88 room at (0,72) (lines 202-205). phase4.md:45 says Class A is at 'y = 24..111', which is wrong: the strip occupies y=72..159. P1 copied that error. (4) prologue_text_presenter has TEXT_BOUNDS (27,166,266,52) and TRANSLATED_LEFT/RIGHT 34/286. translation_layout returns [] when a line overflows, and the line then falls back to Japanese, so width limits English coverage directly. (5) .claude/orchestrator/state/T-30001/foundation-v1/ does not exist. (6) No mouse or pointer handling exists in ui/*.gd or playable_boot today, so the pointer transform is a contract for future input rather than a fix for live input.
- Model. NativeFrameLayout is a pure geometry module. It maps a window size and prefs to: logical width Wl (320 for original, otherwise round(240*W/H) made even and clamped to 320..560), a scale factor (integer floor >=1 when filter=integer, fractional otherwise), an aperture rect (the 320x240 centre in window pixels), wing rects, text_band (the window rect over native rows 160..239, optionally widened into the wings) and the window<->native point transform. aspect=original gives exactly today's first_arrival_boot result: a 4:3 box centred with black bars. aspect=wide uses Wl from the window ratio. aspect=auto means wide when W/H >= 1.5, otherwise original. The existing enum [original, wide, auto] is kept, so no settings migration is needed during T-30002.
- WideFrameComposer turns the native 320x240 Image into a presentation Image of size Wl x 240. It blits the native Image byte for byte at x=(Wl-320)/2 and fills the wings through a provider chosen by SceneAperturePolicy. The default provider is black for every class. Class A (command screen 0x34, school day 0x40, club 0x42) can opt into a source-derived checker-wing provider that continues hud_compositor's checker tile at the same UV, season and fade into x<0 and x>=320. The room strip, actors (walk targets x=-16 and x=340) and HUD stay clipped to the centre. Class B (VN, BUSTUP) and Class C (title, calendar, CG, ending, movies with OPENXA 288x192 inside 320x240, TACO, RPG_BAT, TAIIKU, EN_NICHI) are always pillarboxed. When aspect=original the composer is bypassed completely.
- Modern text box (the main English readability win). It is an opt-in, window-space Control (Label/RichTextLabel with an opaque window-styled panel) drawn above the displayed TextureRect over text_band. It covers the native message window only in the displayed layer, and the fidelity Image is never modified, by construction. Text comes from the generic source-keyed text layer (services/text_layer_store.gd, text_translation_store.gd) keyed by the same line ids the prologue presenter uses. It respects accessibility text scale, and in wide mode it may widen into the wings. Native-glyph English (the current translation_layout) remains the default. Track a metric for how many lines translation_layout rejects (Japanese fallbacks), so the user can judge the value of the modern box.
- Settings. Keep 'Aspect layout' [original, wide, auto]. Add display.wing_fill [black, source] (source applies only where the policy proves it, which today means Class A checker) and accessibility.text_box [native, modern]. Defaults match current behaviour: original, black, native. These apply live without Keep/Revert. Remove settings_runtime's content_scale_aspect/stretch writes only after auditing every scene that relies on project.godot's canvas_items 640x480 stretch (settings menu CanvasLayer, first_launch_setup, title_continue, new_game_entry.tscn, shell.tscn). If any scene depends on them, pin those writes to neutral KEEP/FRACTIONAL values instead of deleting them.
- Integration. One NativeDisplayHost node owns the TextureRect, the composer, the wing provider and the text overlay mount, and re-lays out on viewport resize and on ModernSettings.preferences_changed. first_arrival_boot, new_game_entry_boot and playable_boot each replace their fit code with the host. For playable_boot this means removing scale=2 and the 640x480 backdrop and moving to a texture-presented canvas, which needs care because it currently draws a Node2D canvas, not an Image. Because these files have uncommitted in-flight core-port edits, the root agent applies integration last and serially, starting with new_game_entry_boot, then first_arrival_boot, then playable_boot.
- Verification (Docker tokimemo-port, Xvfb). (a) Fidelity matrix: sha256 of the native Image (last_rendered_image) per frame must be identical for aspect {original, wide, auto} x filter {integer, nearest, linear} x window {640x480, 960x720, 1280x720, 1366x768, 1920x1080, 1920x1200, 2560x1080, 3440x1440}. Run it on the opening route (tests/fixtures/opening_frame_timing.json) and the new-game handoff, together with RNG call counts and GameState hashes. (b) Composer invariant: the centre crop of the presentation Image equals the native Image byte for byte. (c) Integer-mode window grab: crop the aperture, nearest-downsample by k, and the result must byte-match the native Image. (d) Checker seam test: columns x=wing-1 and x=wing match the tile function in all 4 seasons and at fade values 239 and 255. (e) Original-mode regression: rerun tools/port/run_emulator_vs_godot_audit.py and compare_capture_pair.py with aspect=original and expect zero new diffs. (f) Contact sheets per scene class x JA/EN x aspect x size, written to a gitignored .asset-cache dir, for visual review of overflow, seams and readability. (g) Pointer round-trip unit tests. Headless runs do not prove HiDPI or fullscreen behaviour on macOS or Windows; record those as manual checks.
- Deferred, separate tickets: (i) authored-margin reveal for the 640x160 prologue board (P_01_02.BS, scrolled by prologue_board_scroll) and the four 384x160 BS images, only after a source draw-crop trace proves which pixels are shown; (ii) Tier 2 Wide Layout that widens native HUD and dialogue primitives; (iii) ambient blur wings; (iv) wide-HUD readouts in the wings sourced from the live_hud_adapter state. Each needs a user decision first.
- Wiki hygiene first (WP0): amend T-30001 acceptance (window-space aperture, no 426x240 game canvas, remove the nonexistent foundation-v1 reference), fix phase4.md:45 Class A to y=72..159, and update widescreen-settings.md with the checker-wing finding. The root agent owns wiki/log.md, wiki/kanban.md and the ticket status moves. Create the child tickets from the work packages below.

## Settings

Rationale: Proposal B's diagnosis of the persistence and framing problems is the more accurate one. In code, validate() rejects incomplete files wholesale, apply_preferences sets the window-wide stretch and aspect, and the boots each fit the native canvas their own way (first_arrival_boot.gd:55, new_game_entry_boot.gd:119, playable_boot.gd:467). Splitting the menu first is required for file-disjoint parallel work. Proposal A adds what B lacks: presets as value bundles with differs-from-original markers, the drawable-size readout, read-only native voice_mode, and features gated on a capability flag. The merged plan also gives the framing seam a single owner, display_frame_service, which existing boots adopt with byte-identical canvas hashes as their gate. That lets T-30001 widescreen build on it without fighting settings_runtime. Language becomes a semantic choice resolved from the installed profile, so derived data stays out of the repo. Opening the language packs is async, because the synchronous 24.5 MB open would otherwise freeze the menu. Every package carries the native-canvas invariant, so Original mode stays exact. All user-facing choices default conservatively, can be changed later, and are listed for review on the user's return.

### Plan

## Goal

Port `scene_library.c`, `scene_display.c` and `hud_panels.c` onto the engine, following [[engine-porting-contract]].

## Acceptance criteria

- [ ] Every function of these files is ported, with function-differential tests from emulator captures, or listed as untested with a reason.
- [ ] The core suite, `run_engine_diff.sh --all` and the opening frame-timing gate pass.

## Notes

Package notes of the WP-B worker (branch `port/m2-engine-b-scene-hud`). Contract: [[engine-porting-contract]].

**Method.** The three files (164 functions) are ported by a generator, committed in `tools/port/engine_gen/` (inputs in `config/port/engine-gen/`, image `tools/Dockerfile.engine_gen` with pycparser 3.12 pinned, wrapper `tools/port/run_engine_gen.sh`; `--check` fails when a committed `port/godot/engine/{hud_panels,scene_display,scene_library}.gd` differs from the output, `mkspec` writes `config/port/engine-diff/<unit>.json` from the captures, `capture_cmd` prints the capture command with the external callees; tests in `tools/port/engine_gen/test_cgen.py`). The generated modules are not edited by hand: change the generator or the config. It works as follows: `gcc -E` of `src/main/<file>.c`, pycparser, then a typed translation to GDScript that follows the contract. What it applies, so a reviewer can check the GDScript against the C statement by statement:
- K&R integer promotion (`-cckr`: `u8`/`u16` promote to unsigned int, `s8`/`s16` to int), 32-bit wrap written out (`Math.s32/u32`) only where an interval analysis allows an overflow, narrowing at every store to a local and at function entry for every parameter (`Math.u8(arg)` etc., so a caller's `(s32) address` or an unsigned `-1` is canonical inside).
- Memory through `engine.memory` with the C types; `game_state` scalars through `engine.gs_get/gs_set`; scalar globals through `read_global/write_global`; every other global through a named address constant (`G_<NAME>`, the address of `core/game_layout.gd` or `config/symbol_addrs*.txt`); struct offsets computed from the headers (bit-fields included) and cross-checked against the layout for every `game_state` field.
- Calls through `engine.call_c`; a call that passes more arguments than the callee's C definition takes drops the extras with a comment (see below); `while`/`for` loops whose condition or body calls out test `engine.halted()`; `switch` becomes `match`; the two `goto` labels of `talk_render` become a loop with `continue` and an inlined forward label.
- Locals on the stack (arrays and structs, `STACK_LOCALS` in the generator) live at `engine.frame_base() + <original offset>`; the offsets of arrays passed to callees are the `addiu $reg, $sp, N` of `asm/matchings/main/<file>/<function>.s` (hud_icon_layout_apply x 0xC0, y 0xA0, w 0x80, h 0x60; the two/three select init x, y, w, h; talk_speak_part line_buffer 0x7C, speaker_name_fragment 0x74, speaker_name_text 0x68, voice_speaker_ids 0x58; talk_render line 0x2A4, name 0x28C, text 0x8C, open 0x84, punct0..4 0x80..0x70; make_three_select option_text_buffer 0x64; select_girl_init label 0x64). Local-only arrays (hud_icon_move_allowed cx/cy, hud_screen_frame_draw enabled, select_girl_by_scores list) sit at free slots of the frame, because IDO keeps them in registers.
- String literals are rodata addresses: IDO does not pool strings, so the i-th literal of `scene_library.c` is the i-th string of `asm/data/main/scene_library.rodata.s` (125 literals, 125 rodata strings, matched in source order; `""` is a 4-byte zero word each). Array initialisers (`u8 punct0[3] = "..."`) are byte writes.
- A local that the C may read before it assigns it holds stale stack bytes: `portrait_build` (`origin_x`, `origin_y` for a frame with 4 or 5 parts) and `select_girl_init` (`result` with no enabled girl and `omit_back` set) refuse (`_uninit`) instead of inventing 0; every other local is assigned before it is read (a definite-assignment check over the C found no other case; `talk_speak_part.p` is a false positive: the loop only exits after assigning it).
- Struct sizes and field offsets are named constants (`ACTOR_SIZE`, `ACTOR_DRAW_FLAGS`, `SPRITE_QUAD_UNK_0C`, ...) from the headers; local arrays that IDO kept in registers (`hud_icon_move_allowed` cx/cy, `hud_screen_frame_draw` enabled, `select_girl_by_scores` list) are GDScript `Array[int]`; lines are wrapped at 120 columns; every function has a `##` comment (the C comment, or the list of its callees). The generator refuses (the function is left out, `--check` fails) a `continue` or `goto`-continue inside a `switch` arm (GDScript reads it as a pattern fall-through), an expression statement with side effects that is not an assignment, increment or call, and any string literal it cannot match to the rodata.
- Return values: a function that falls off its end says so (`ret_undefined`, or `ret_defined: [constants]` when the other paths return constants, for example `normal_date_girl_in_main`).

**C quirks found (report to the orchestrator, no `src/` change made).**
1. `message_window_set_title_hidden(void)` and `portrait_read_step(void)` had no parameter in the C although every caller passes one and the function forwards `a0` (the harness hit shows `a0 = 0x800B1590`, a title string). Orchestrator-approved one-time `src/` change: they now take and forward `u8 *arg0` and `s32 arg0` (`src/main/hud_panels.c`, `scene_display.c`, `include/main/message.h`, `include/main/portrait.h`, and the `MAIN_API_OVERRIDE_message_window_set_title_hidden` in `scheduler.c` is gone). Decomp build gate: `tools/docker.sh ninja` in a copy of the tree with the user's `disc/files` and `asm/` (the worktree has no game data): `build/SLPM_86.053.bin` has SHA-1 `e823bd844a8f8fa4d05483b59c66bc54b8393b26` (equal to `config/SLPM_86.053.sha1`) and every overlay prints OK (26 overlays + the executable = 27); `funcdiff.py message_window_set_title_hidden` is a MATCH.
2. `portrait_value_clear_if_high(void)` is called with an argument by `portrait_build`, `portrait_layout_set` and the overlays. Giving it a parameter does not match (`tools/funcdiff.py`: the original has `nop` where IDO now spills `sw a0,0(sp)`; real difference), so the C keeps `(void)` and the port takes the argument through a documented signature override: `"args_extra": 1, "args_extra_reason": "..."` in `C_SIGNATURES`, which `tools/port/check_engine_signatures.py` accepts (the C count plus `args_extra`, a reason is mandatory). The signature check is at 0 errors.
3. `sprite_brightness` is defined in `scene_library.c` (O.BIN name); `func_80084C98` is its alias (same address), the calls are written as `sprite_brightness`.
4. The sound functions `SD_GetCDLevel`, `SD_DetectCDPeak`, `SD_CalcCDAve`, `getCDlevel` and `addr_init_*_sd` live in this mixed object; they are ported here like everything else defined in the file.

**Test and spec decisions.**
- The libcd/SDK/BIOS ranges the vertical-blank and CD interrupts change while a function runs are excluded as in `cd_queue.json` (same ranges, same reasons). `portrait_show_checked` runs `cd_file_checksum_ok` over a whole file, so the original's interrupt handlers run inside the call and change the sound driver, flag and actor bytes; its function-level exclusions list the bytes the capture shows (one-sided, the port's own range `0x8011F50D+67` is `port: free` because `portrait_build` rewrites actors 30 and 31).
- Captures that record a pointer into the stack compare 64 bytes behind it by default; arrays smaller than that are followed by the original's spill slots (`hud_icon_layout_apply` saves its zero index at `sp + 0xE0`), so every `wpb-*` capture after the first used `--ptr-bytes 32`.
- `tests/engine/engine_core_test.gd` and `diff_harness_test.gd` (base worker) used `message_window_title_show` as the example of an unported callee. Their refusal examples now call `__test_never_ported` (a double for `message_window_title_show` in the core test, a test module in the harness test), so no package has to touch them again (orchestrator-approved edit, for that purpose only).
- Spec exclusions are per function: no blanket BIOS/SDK/libcd ranges. `message_window_title_update` lists the kernel range and four single bytes (a vertical-blank interrupt inside 4 hits); `portrait_show_checked` lists the 61 exact byte runs the capture shows changing before its first callee call (interrupts inside `cd_file_checksum_ok`), of which only the 9 actor-31 runs that `portrait_build` also writes are `port: free`.
- `sprintf` is the SDK layer's ([[tickets/T-39314-engine-sdk-layer]], merged); the hand checks of `talk_speak_part` (speak codes 0x0 0x1 0x7 0xA 0xB 0xC 0xE 0xF and the earlier ones) and `make_three_select` use a double for it that formats the one format the C uses, because the format and name literals are rodata that invented memory does not hold.
- Hand checks (invented memory, expectations derived from the C): `tests/engine/hud_panels_test.gd`, `scene_display_test.gd`, `scene_library_test.gd`.

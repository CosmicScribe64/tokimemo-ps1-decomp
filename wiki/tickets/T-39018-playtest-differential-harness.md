Real-time PCM is not reproducible: before the Rei start the backend renders what the wall-clock device drains (17905 blocks before tick 4572 at about 14.7 logic frames/s, against 4345 in FAST), and the native engine state at the Rei start depends on how many blocks the wall clock drained, so real-time race PCM depends on host speed from the first block (a review rerun differed at race block 0). Faster-than-real-time routes need those per-frame costs cut; FAST mode removes the GPU, PulseAudio and xdotool dependence and makes native PCM reproducible.

- Changes. None of them changes a digest value or a guard. (1) `FrameResult.event_hash` is rendered on first read. `GameSession.step` captures the records at commit (deep copies of presentation, audio, transitions and the RNG slice, and a list copy of the session-owned trace snapshots), so a read returns what an eager digest at commit returned, even after a later edit of `result.presentation`. A rollback still clears the digest. (2) `state_hash` digests the same text: `GameState.words_json()` (new `core/canonical_words.gd`) renders `JSON.stringify(to_words())` without the per-byte list. Each record's byte text is cached under its exact `var_to_bytes()` encoding (exact for value, type and key order), and a subclass that overrides `to_words()` falls back to it. The session reuses the digest only when the full text is identical. (3) The upload `_runtime_hash` keeps each buffer's SHA with a private copy of the bytes. A byte-exact compare (about 27 us per MiB) replaces the SHA. It is a copy because a packed array held in a Variant is shared, and the unit test caught the in-place write. (4) Upload readiness results are cleared only when publish executes a batch (the only thing that changes pump receipts). They are reused only while the owned buffers equal an exact deep copy. That is stronger than the old spot check. Tests: `tests/core/run_state_digest_tests.gd` (in `run_tests.gd`, 7 suites PASS).

- Dev checkpoints. These are development only. `tests/checkpoint/runtime_checkpoint.gd` saves and resumes the whole port runtime at a frame boundary (the observer `_process` after the logic frame). It captures every script object reachable from the app and `/root/ModernSettings` (breadth-first, so an object the booted app already holds has the same path), every script variable, and container sharing (two holders of one Dictionary still share it). It also captures typed arrays and dictionaries, images, WeakRefs, bound callables, native resources by storage, signal connections between graph objects, node children, order, priority and groups, the command HUD's `_outer_frame_guard` static, and the observer, receipts and FAST-helper plain variables. It replays the native OriginalAudioEngine's call log (`tests/checkpoint/engine_recorder.gd`, a generated forwarding wrapper installed through the new inert `bgm_backend.gd` seam `engine_factory`) into a fresh engine and checks every result digest, with host timing fields left out. A resume reuses the booted app's natives and lambdas at the same path and refuses when one is missing. The runner is `tools/port/run_installed_route.sh --fast --checkpoint-save` (writes `<out>/runtime-checkpoint.bin` at `TOKIMEMO_DEV_CHECKPOINT_KEY`, default 34/1/0/0) or `--resume <checkpoint>`. Both need `--fast` and `ROUTE_OBSERVER=playtest`. The checkpoint carries the route identity (the SHA of every candidate-hashes line but mode: bundle, library, bridge, HEAD, working-tree diff, sources), and a resume under other code refuses ("checkpoint was written for another route identity", shown). A resumed run writes `resumed-from.json`. `compare_route_modes.py` refuses it unless given `--resumed`, and `compare_newgame_golden.py` refuses it (exit 2). The timing and acceptance checks are never reached in a resumed run.

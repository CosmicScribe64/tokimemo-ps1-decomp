## Goal
Roadmap phase 2 for unit o-tt (overlay TT, 303 functions, `src/ovl/TT`): name the entry point, the scene state machine, every function of the game logic and the data tables it reads, and write the scene-flow spec for the port. Analysis only: renames are applied later, after asking the TT contributor (issue CosmicScribe64/tokimemo-ps1-decomp#2).

- [x] `config/renames/proposals/o-tt.tsv`: one row per rename (func, data, field, type, file, const), one name per address, notes carry the evidence, game-meaning guesses start with HYPOTHESIS
- [x] `wiki/spec/o-tt.md`: state machine, state and data, rules, connections, open questions; linked from `wiki/spec/index.md`
- [x] Emulator checks of the main claims (title, stage, boss, ranking, state sequence, direct mode); states stay under `build/emu/` (ignored)

- [x] Review against `CODING_STANDARDS.md` (nothing in src/ changed: only tables and wiki pages); approved after three review rounds

## Notes
- Identity: the overlay is the whole TwinBee Time Attack game (vertical shooter judged by clock time). The emulator title screen confirms the name. Prefix decision: `tt_` for functions and data, `Tt*` for types (existing), folder `src/ovl/twinbee_time_attack/`.
- Result: 995 rows: 303 function, 165 data, 41 type, 291 field, 163 const, 32 file (31 .c files and the header include/ovl/TT.h); 42 start with HYPOTHESIS.
- Port-first scope: game logic fully named; the draw, VRAM, CD and sound layers only by module and entry point.
- Local emulator patch (pokes from `build/emu/pokes.txt`) was used to start the overlay at the title and in direct stage mode; it is not part of the commit.

### Review approved (2026-10-24)

Third review: approved, no findings. The blocking bell finding from round 2 is fixed, and no clear factual errors turned up in the rows or lines the fix touched (commit 0bc1c7a32).

Bell hazard, checked against the C:
- `func_8013C41C` (`src/ovl/TT/8013BD10.c`) increments the counter first. A hit on a state 0x60 bell with the counter at 4 or more sets state 0x70, velocity +0x20000 (2 px per frame), acceleration 0 and x velocity 0, then returns without bouncing. A hit on a 0x70 bell plays SE 0x60C and frees it. The break resets the counter to 0 and the kind comes out as 0.
- `func_8013C048` frees a bell below y 0x100.
- `func_80144A04` (`src/ovl/TT/80142D40.c`) case 0x70: if the player's byte 0x52 (invulnerable) is 0, it calls `tt_player_hit`, sets player state 0x60 and frees the bell.
- `func_801455C8` (`src/ovl/TT/80144D70.c`) calls the collect function only while the ship is in state 0x30 or 0x40, using the hitbox 0 against hitbox 4 test.
- Spec 6.4, 6.9 and the `TtBell.state`, `tt_bell_hit_by_shot`, `tt_bell_collect`, `tt_collisions_update` and `tt_anim_list_bell_fall` rows all match. No "vanish" or "collect" wording for state 0x70 remains in the spec or table.

Other touched rows, checked:
- The boss 4 beam tables match the asm data: 5, 5, 5 and 4 s32 entries with mirrored pairs, pattern a when boss byte +0x106 is 0. `D_80155F14` is only the end bound of the b loop, as its new row says.
- The boss 2 hitbox slot installs match `tt_boss2_init` (`func_80135870`).

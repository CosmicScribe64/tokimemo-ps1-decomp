# T-30005: widescreen and modern settings feasibility

Research only, 2026-10-25. Recommendation for the later modernization: support modern window/output sizes while preserving each scene's original composition. A widescreen interface around an aspect-preserved scene is feasible without new art. A universally filled widescreen picture is not supported by the available evidence. Higher output resolution enlarges existing pixels; it does not add image detail.

Prefer original art, uniform scale, UI reflow, verified existing margins and original framing/pillarboxing, in that order as applicable. Image generation/editing is a last-resort future option requiring a separate decision. None was performed. Any later generated extension must be labeled separately from original pixels and remain optional beside an original-art mode. No runtime/source/wiki/gallery/original-data edits or emulator launch occurred in this research lane.

## Recommended scene policies

| Scene | Initial modernization policy | Possible extension after proof |
| --- | --- | --- |
| Room/weekday/holiday panels | Keep the original art aperture and actor anchors; center it in a wider layout. Reflow calendar, commands, status and dialogue into surrounding UI. | Reveal margins only when the same source asset and camera/crop establish them. Do not duplicate edge pixels, mirror rooms or invent extensions as an automatic fit. |
| Dialogue/portraits | Uniformly scale original portrait layers; preserve intentional body/edge crop. Use a separate high-resolution text/choice layout with wrapping and variable height. | Reposition portrait/text groups after eye-line, actor ordering, focus and interaction checks. A cut-off shoulder cannot be recovered by moving the image. |
| Full-frame illustrations/photos/instructions | Original composition with bars; selectable zoom only with a clear crop preview and no lost required information. | Scene-specific approved crops. Filling16:9 from320×240 by crop retains320×180 and discards25% of height; unsuitable as a universal default. |
| Movies | Fit within the proved presentation aperture; bars are acceptable. Keep subtitles in a separately scalable safe region. | Optional crop after shot/subtitle inspection; no motion interpolation or generative extension in this research. |
| 3D title/shooter | Minimal first design retains original framing, with optional higher-resolution rasterization once faithful renderer exists.| A later wider horizontal field of view can retain vertical framing, but must audit missing geometry, culling, offscreen spawns, backgrounds, scripted entrances, HUD and difficulty. Camera presentation must not expand collision/activation areas. |
| Sports/minigames and exceptional video modes | Preserve original playfield and mode-specific aspect; place additional UI outside. | Widen only after gameplay/camera/edge review; generic `expand` changes visible area and can change challenge. |
| Settings/save/other modern UI | Responsive containers/anchors, scalable text and consistent margins, independent of native scene resolution. | Full widescreen layout is practical without modifying game artwork. |

Godot supports viewport-fit, integer scale and aspect preservation; `canvas_items` draws at target resolution, while `viewport` first renders a fixed raster. `expand` increases visible canvas area, not art supply. Proposed architecture: an aspect-aware native-art viewport plus a separately sized modern Control layer; avoid scaling already enlarged640×480 output when the intended unit is one native pixel. This is a design recommendation, not a tested replacement for the current renderer. [Godot4.7 multiple resolutions](https://docs.godotengine.org/en/4.7/tutorials/rendering/multiple_resolutions.html), [Control anchors](https://docs.godotengine.org/en/stable/tutorials/ui/size_and_anchors.html). For later 3D, `Camera3D.keep_aspect` can lock the vertical axis, but does not audit scene completeness. [Camera3D](https://docs.godotengine.org/en/stable/classes/class_camera3d.html).

## Scaling and filtering

Default proposal: nearest sampling with integer scale for original sprites/glyphs, aspect-preserved fit, neutral bars. Offer a clearly named smooth fit using linear sampling; it softens boundaries and cannot restore detail. Keep modern text/UI scale independent. Godot exposes nearest/linear per CanvasItem, allowing movie/painted-background preferences without blurring pixel glyphs. [CanvasItem filtering](https://docs.godotengine.org/en/4.7/classes/class_canvasitem.html#enum-canvasitem-texturefilter).

For a square-pixel320×240 digital scene in an actual1920×1080 drawable area, integer4× produces 1280×960 with320-pixel side and60-pixel top/bottom bars. Fractional fit4.5× produces 1440×1080; nearest distributes source pixels across unequal output widths, while linear blends them. At 1280×720, integer3× gives 960×720; at 2560×1440,6× gives 1920×1440; at 3840×2160,9× gives 2880×2160. These are arithmetic examples, not quality ratings or CRT-mode prescriptions. Compute against the final drawable pixel area, including HiDPI/compositor scaling and decorations, and center on integer output coordinates. Below the native extent, choose a documented fit fallback rather than a zero integer factor.

Direct source inspection of C_01_27's320×88 library room, AS01's144×160 portrait, MAINROM's32×24 frame and SD_P0E's48×64 sprite shows both painted/dithered shading and sharp pixel edges. This supports offering a preference, not asserting one filter looks best everywhere. No comparison mockup was needed; no visual-quality trial has been performed. Neither nearest nor smoothing creates higher-resolution art; mipmap/atlas-edge/STP behavior requires separate tests when downsampling or filtering.

## Modern settings proposal

These are product recommendations informed by official accessibility guidance, not claims that a fixed category list or15-second countdown is an engine standard. Make settings reachable at startup and from pause; provide mouse click/wheel/drag and complete keyboard/D-pad navigation, visible focus, predictable focus order, current values, short explanations and cancel/back. Avoid hover-only help and drag-only sliders; digital left/right must also adjust values. [XAG112 UI navigation](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112), [XAG107 input](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107).

| Category | Recommended controls and limits |
| --- | --- |
| Display | Windowed/fullscreen mode, monitor where supported, window size, original framing/adaptive UI, integer/fit and safe margins. Show effective drawable size; fullscreen output follows the desktop mode, so do not label a window/render-size selector as a monitor refresh/mode switch. |
| Graphics | Original-art filter, optional higher-resolution 3D only when implemented, supported V-sync behavior and optional render cap. Avoid nonfunctional HDR, ray tracing, texture quality or blanket upscaler toggles. Godot4.7 documents Compatibility restrictions and fallback to enabled V-sync; do not promise an effective Off/adaptive/mailbox choice. Compare the requested setting with engine readback and verify actual target-platform presentation before exposing choices; readback alone is insufficient. |
| Audio | Master/music/voice/effects with numeric values, mute and a short user-triggered preview. Use perceptual slider mapping; zero is mute. Presentation gain/mute must not stop audio completion, voice/lip timing or advance story rules. |
| Controls | Keyboard/mouse/controller tabs, multiple bindings, restore defaults, confirm/cancel convention, prompt style auto/manual, stick deadzone and menu repeat calibration. Show conflicts within each context and offer replace/swap/cancel; block loss of all navigation/confirm/back bindings. Support controller reconnect and keyboard escape from rebinding. |
| Accessibility | UI/text scale, subtitle size/background/contrast and speaker labels, text speed/instant text, reduced presentation flashes/shake where implemented, hold/toggle alternatives and no reliance on color alone. Separate gameplay assistance from faithful rules; never silently change timing/scoring. Native bitmap text has size limits; scalable translated/accessibility text requires its own layout. |
| Language/content | Independent interface/text language, validated translation-pack selection/version/credits/coverage, original fallback, and separate voice language only where actual audio exists. English text must never imply an English dub. Translated image-text variants require supplied assets; fallback remains clear. Preserve content IDs, save compatibility and the user-owned Gemini workflow. |

Keep Godot's UI focus actions separate from gameplay actions. InputMap supports runtime event bindings and per-action deadzones; explicit focus neighbors avoid layout-dependent surprises. Store abstract actions then translate to native fixed-step inputs, preserving edge/repeat/latch semantics. Clear held inputs around settings/focus transitions and consume the dismissal input before resuming. Controller support does not establish every device/platform works. [Godot focus/navigation](https://docs.godotengine.org/en/stable/tutorials/ui/gui_navigation.html), [InputMap](https://docs.godotengine.org/en/stable/classes/class_inputmap.html), [Godot4.7 controllers](https://docs.godotengine.org/en/4.7/tutorials/inputs/controllers_gamepads_joysticks.html).

Make text size and subtitles available before gameplay; test long translations, speaker identity, background contrast and viewing distance, rather than prescribing a single pixel size at every resolution. Audio captions need authored/validated content; a toggle alone cannot supply them. [XAG101 text](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101), [XAG104 subtitles/captions](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/104). Separate audio buses support independent category gain. [Godot audio buses](https://docs.godotengine.org/en/stable/tutorials/audio/audio_buses.html).

## Safe apply, persistence and platform limits

Stage display mode/monitor/size changes; capture the last confirmed configuration, apply temporarily, show an explicit Keep/Revert dialog with a proposed 15-second monotonic wall-clock countdown. Revert on cancel, timeout or lost focus while unconfirmed; never auto-keep. Settings UI countdown must run independently of paused gameplay. Persist the pending marker before applying; after a crash or failed restart, recover the last confirmed display, or a safe visible window if its monitor disappeared. Do not overwrite last-known-good settings with tentative values. Handle confirm safely at small sizes and 100–200% UI scale. The countdown and recovery mechanism require app code and tests; Godot does not supply this complete policy.

Before applying, provide an accessible longer confirmation-time option, such as 60 seconds, while retaining bounded automatic Revert. Put initial dialog focus on Revert, consume the applying input, expose the deadline and button semantics to narration, and announce a useful warning without reading every tick. Test the extended interval with keyboard/controller and assistive navigation; ordinary settings pages should have no time limit. These are proposed design values, subject to accessibility testing. [XAG116 time limits](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/116).

Start in a visible resizable window clamped to the current usable display area. Offer fullscreen choices only where supported. Godot's two fullscreen modes do not switch the monitor's video mode; macOS uses a separate desktop, Wayland treats exclusive like ordinary fullscreen, and platform capture/compositor behavior differs. Integer-fit must use the real drawable size, including the documented Windows fullscreen height caveat. Headless/Xvfb tests cannot establish native desktop display behavior. [Godot4.7 DisplayServer](https://docs.godotengine.org/en/4.7/classes/class_displayserver.html).

Preview low-risk sliders immediately, with per-category Restore defaults and a clear apply/discard rule for remaining changes. Persist a versioned, validated primitive settings record under user storage, separate from game saves/replay state; ignore invalid values and retain recovery controls. ConfigFile supplies configuration storage, not schema migration or atomic last-good recovery. [ConfigFile](https://docs.godotengine.org/en/stable/classes/class_configfile.html). Godot supports locale selection/resource remaps, but the port still needs validated external packs and stable IDs; native resource remapping is not a reason to put original assets inside res://. [Internationalization](https://docs.godotengine.org/en/stable/tutorials/i18n/internationalizing_games.html).

## Decisions and validation still needed

Approve the scene policy and proposed original-framing default before design implementation. Then test 720p/1080p/1440p/4K, 16:10/ultrawide, small windows, HiDPI and long text on actual target desktops. Compare whole composed scenes and scrolling/motion under nearest/integer versus smooth fit; check actor edges, atlas bleed, STP/blending, dialogue choices and mouse hit transforms. Establish special-mode pixel aspect and movie placement before exposing corrected-aspect choices. Audit each wider 3D camera with original gameplay replays and all scripted edges; art availability alone is insufficient.

Settings acceptance must cover keyboard-only/controller-only/mouse navigation, focus loss, device unplug/reconnect, remapping conflicts/recovery, timeout/crash/unplugged-monitor rollback, corrupt settings, audio-muted timing and unavailable language/voice/image variants. Re-run game-state/hash comparisons at multiple render rates and display settings. No resolution, filtering or navigation quality is proved by this research-only audit. Independent Standards and source/spec reviews passed; T-30001/2 implementation remains separate from faithful Phase3 acceptance.

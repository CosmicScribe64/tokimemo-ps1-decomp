# Raw source note: identifying the original game-code compiler (T-3100)

Collected 2026-10-09 by reading public web pages, man pages and source listings, and by analysing the game's own files under `disc/` and the IDO 5.3/7.1 recompilations already in the Docker image. No compiler binary, OS image or archive was downloaded or run apart from those two IDO versions. Two PDFs that the fetch tool could not parse were cached automatically by the harness outside the repository (a WIDE 1992 report and a Psy-Q document); they were not read and are not cited as read. "UNVERIFIED" marks claims not traced to a primary source. Quotes are short; everything else is paraphrase.

## 1. Local measurements (reproducible in Docker)

- O.BIN header fields: `tools/docker.sh python3 tools/obin_syms.py --headers` (values copied into [[original-compiler]]).
- Version stamps written by the in-image IDO: compile any C file with `/opt/ido/5.3/cc -c -O2 -EL` and read the `.mdebug` symbolic header: IDO 5.3 writes HDRR magic 0x7009, vstamp 0x0313 (3.19); IDO 7.1 writes 0x070A (7.10). The `.mdebug` section is big-endian even in `-EL` objects.
- IDO 5.3 `cc`, `cfe`, `uopt`, `ugen`, `ld`, `strip` carry `@(#)$Header: IRIX 5.3:1021572033 built 11/03/94`; `as1` carries a patch build of 01/18/96. The `cc` driver has the format string `Mips Computer Systems %d.%d` (strings read from the byte-swapped data of the recomp binaries).
- IDO 5.3 `ld` has no COFF/ECOFF output strings; its version-stamp messages are `version stamps in object inconsistent %d.%d and %d.%d` and `version stamp: %d.%d, does not match %s's: %d.%d`.
- uopt 5.3 option table (byte-swapped strings): `-regr`, `-rege`, `-nomultibbunroll`, `-unrolllimit`, `-loopunroll`, `-Olimit`, `-varref`, `-trapuv`, `-fp32reg`, `-strictIEEE`, `-64data`, `-dwopcode`, `-mips1..4`, `-nokpicopt`, `-kpicopt`, `-pic2`, `-static`, `-no_r23`, `-moremotion`, `-fortran_lang`, `-noPalias`, `-f77alias`, `-createbb`, `-nordstore`, `-domtag`, `-notail`, `-nogenvreg`, `-norecur`, `-docodehoist`, `-no_const_in_reg`, `-do_opt_saved_regs`, `-noheurAB`, `-norlodrstropt`, `-noprecolor`, `-dowhyuncolor`, `-doassoc`, `-docopy`, plus debug flags `zdbug`, `zaloc`, `zscm`, `zstor`, `zcomo`, `zcopy`, `zmovc`, `zvref`, `zmark`. `-Wo,-zdbug:6` aborts in the recomp (`wrapper_ecvt: Assertion '0' failed`), lower levels print the flow graph and then stop at 4096 bytes.
- ISO 9660 primary volume descriptor of `disc/track1.bin`: publisher `KONAMI_KCET`, data preparer `K_FUKUHARA`, volume set `TOKIMEKIMEMORIALBEST`, created 1997-12-25 (the Best reissue). The copyright field (`disc/layout.xml`) is `KCET_KONAMI`.
- Identification-string scan of `SLPM_86.053`, the 26 overlays, O.BIN and the whole raw `track1.bin` (grep for `$Header`, `@(#)`, `$Id:`, `NEWS`, `/usr/`, `/home/`, `Mips Computer`, `MIPS`, `ccpsx`, `psylink`, `PSYQ`, `Psy-Q`, `SN Systems`, `ULTRIX`, `IRIX`, `Copyright`): no compiler, assembler or linker string. Only the three PsyQ RCS ids already known ([[psyq-sdk]]), the SCE copyright, the licence text, and two game-side source names in error strings: `BG_ERROR:p_line.c` and `<kanji.c>error(No-sjis)` (main exe, file offsets 0x6F2E0 and 0x6F350).

## 2. ECOFF format and version stamps

- vstamp = major in the high byte, minor in the low byte, minor written in decimal: Ultrix `stamp.h` defines `MS_STAMP 1` and `LS_STAMP 31` ("ULTRIX stamp.h 4.2", quoted in an Athena bug post) https://diswww.mit.edu/menelaus/bugs/6259 ; gas `ecoff.c` documents a symbolic header dump with "magic number = 0x7009, vstamp = 1.31" and says the field holds "a MIPS compiler version number, such as 2.0". https://gnu.googlesource.com/binutils-gdb/+/master/gas/ecoff.c . Packing (MS<<8)|LS is an inference from these two plus the local IDO measurements above.
- a.out optional header has `vstamp` ("version stamp"): https://gnu.googlesource.com/binutils-gdb/+/master/include/coff/mips.h . HDRR `magic` + `vstamp`: https://gnu.googlesource.com/binutils-gdb/+/master/include/coff/sym.h . `magicSym` = 0x7009: https://gnu.googlesource.com/binutils-gdb/+/master/include/coff/symconst.h . BFD copies the symbolic-header stamp into the optional header (`internal_a.vstamp = symhdr->vstamp;`) and sets F_AR32WR for little-endian output: https://gnu.googlesource.com/binutils-gdb/+/master/bfd/ecoff.c .
- The linker writes the stamp: `ld -VS num` "sets a decimal version stamp" stored in the optional and symbolic headers, in both NEWS-OS 4.2.1R ld(1) https://typewritten.org/Manual/Sony/NEWS-os/4.2.1R/en_US/man1/ld.html and Ultrix 4.4 ld(1) https://typewritten.org/Manual/DEC/Ultrix/4.4/mips/man1/ld.html . `-N` gives OMAGIC 0407.
- File header flags: F_RELFLG 0x1, F_EXEC 0x2, F_LNNO 0x4, F_LSYMS 0x8, F_MIPS_NO_SHARED 0x1000, F_MIPS_SHARABLE 0x2000, F_MIPS_CALL_SHARED 0x3000, F_MIPS_NO_REORG 0x4000, 0x8000 = F_MIPS_NO_REMOVE ("Do not remove nops"); a.out magics OMAGIC 0407, NMAGIC 0410, ZMAGIC 0413. Source: Tru64 Assembly Language Programmer's Guide, ch. 7 (object file format), https://ftp.zx.net.nz/rom/V4.0D_D1/DOCS/HTML/APS31DTE/DOCU_013.HTM . Ultrix 4.4 filehdr(5) lists only the four low flags: https://typewritten.org/Manual/DEC/Ultrix/4.4/mips/man5/filehdr.html . No source found for 0x8000 in pre-OSF MIPS toolchains (UNVERIFIED there).
- No source found for any linker that writes one section header in host byte order inside an otherwise little-endian ECOFF (UNVERIFIED; the observation in O.BIN is ours).
- No source found for PsyQ/psylink ECOFF output or its vstamp (UNVERIFIED).

## 3. Version tables

- SGI FAQ (apps, item 34, dated 12 Jun 1994): IRIX 4.0.x uses IDO 4.1.1 with C 3.10.1 and the 3.12 back-end; "IRIX 5.2 needs IDO 5.2, which includes C 3.18". https://magog.ldeo.columbia.edu/documentation/sgi-faq/apps/34.html (read directly).
- IRIX release dates: 4.0 09/1991, 5.0 03/1993, 5.1 09/1993, 5.2 03/1994, 5.3 11/1994, 6.0.1 12/1994, 6.1 07/1995, 6.2 03/1996. https://archive.irixnet.org/sgistuff/software/irixhistory/index.html
- IDO versions listed (no 5.2 entry, no compiler numbers): 4.0, 4.1.x, 5.0, 5.1, 5.3, 6.0, 6.1, 7.1, 7.1.1. https://tech-pubs.net/wiki/index.php/IRIS_Development_Option
- IRIX 3.3.1 `cc -V` printed "Mips Computer Systems 2.0"; a fix was promised for "2.10 and later". https://ftp.math.utah.edu/pub/mirrors/www.tuhs.org/Unix_Usenet/comp.sys.sgi/1990-November/001355.html . Ultrix 4.0 shipped MIPS compiler 2.00 (Usenet). https://www.tuhs.org/Usenet/comp.unix.ultrix/1990-November/005214.html
- RISC/os: UMIPS 3.10 onward, 5.0 shipped 28 Oct 1991. https://www.tech-pubs.net/wiki/index.php/RISC/OS
- Not found: compiler versions of Ultrix 4.2-4.5, RISC/os 4.5x/5.x, any NEWS-OS release (the NEWS-OS man pages only say `-V` prints pass versions). UNVERIFIED.

## 4. NEWS-OS, Ultrix and OSF documentation of the ucode compilers

- NEWS-OS 4.2.1R `cc(1)`: "the RISC NEWS ucode C compiler", MIPS extended COFF; passes `ccom` (front end), `ujoin`, `uld`, `usplit`, `umerge`, `uopt`, `ugen`, `as0`, `as1`, `ld`; `-O1` default, `-O2` global ucode optimizer, `-O3` adds ucode linking and "global register allocation"; `-Olimit` default 1000; `-G` default 8; `-EB/-EL`; `-mips1` default. https://typewritten.org/Manual/Sony/NEWS-os/4.2.1R/en_US/man1/cc.html ; `as(1)`: big-endian default, `-EL` available, as1 assembles and reorganizes. https://typewritten.org/Manual/Sony/NEWS-os/4.2.1R/en_US/man1/as.html . typewritten.org hosts NEWS-OS 3.3, 4.1C, 4.2.1R and 5.0.1 manuals: https://typewritten.org/Manual/Sony/NEWS-os/
- Ultrix 4.0/4.4 `cc(1)`: same pass list with `ccom`; `-Olimit` default 500. https://typewritten.org/Manual/DEC/Ultrix/4.0/mips/man1/cc.html , https://typewritten.org/Manual/DEC/Ultrix/4.4/mips/man1/cc.html
- OSF/1 1.0 `uopt(1)`: `-O3` uses an "inter-procedural technique" for register allocation, `-loopunroll` default 4, `-Olimit` 500, `-no_r23`, `-zdbug:6` traces global register allocation by priority-based coloring. https://typewritten.org/Manual/DEC/OSF:1/1.0/mips/man1/uopt.html
- Digital Unix guide: `-O2` optimizes within one compilation unit, `-O3` runs uld/umerge then uopt. https://www.cs.auckland.ac.nz/references/unix/digital/APS30DTE/DOCU_009.HTM
- uopt is "not really intended to be under direct user control" (1990 Usenet, example `-Wo,-noPalias`). https://ftp.math.utah.edu/pub/mirrors/www.tuhs.org/Unix_Usenet/comp.sys.sgi/1990-September/000363.html
- No documentation found for `kpicopt`/`nokpicopt`, `-regr`/`-rege`, a 16-byte reserved frame area, or leaf procedures keeping the argument build area. UNVERIFIED.

## 5. Register allocation literature

- Chow & Hennessy, "The priority-based coloring approach to register allocation", ACM TOPLAS 12(4), 1990, pp. 501-536 (journal version of the 1984 SIGPLAN paper); the uopt allocator per the OSF uopt(1) `-zdbug:6` text above. Paper not read (bibliographic).
- Chow, "Minimizing register usage penalty at procedure calls", PLDI 1988, pp. 85-94 (interprocedural allocation, shrink-wrapping, MIPS production compiler): https://www.cs.tufts.edu/~nr/cs257/archive/fred-chow/p85-chow.pdf (scanned image, text not extracted; formulas not read).
- Priority function weights (for example 10^loop-depth): not confirmed in any source read. UNVERIFIED.
- OoT's IDO 5.3 -O2 guide: register order for variables observed as v0, v1, a0..a3, t0..t5; `v0`/`v1` choice marked "TODO"; `-Wo,-loopunroll,0`; `-Wo,-zdbug:n` writes `uoptlist`; `void f(void)` uses 4 more stack bytes than `void f()`. https://github.com/n64decomp/oot/blob/master/docs/guides/-O2%20decompilation%20(for%20IDO%205.3).md
- Decompilations of IDO itself: https://github.com/n64decomp/ido (uopt 7.1 C reconstruction with debugger), https://github.com/LLONSIT/ido-decomp , https://github.com/decompals/ido-matching-decomp (uopt, ugen, as1 are Pascal; uopt unmatched in the snapshot read). The priority code was not located in them in this pass.

- Evo's Space Adventures, re-checked at the coordinator's request (mkst, author of maspsx): a PSX-only matching decomp that borrows code from the N64 version and N64 tooling (splat, asm-differ, permuter), but its build is gcc. README: "This project uses gcc 2.92.2, GNU as, and `maspsx`"; Makefile: `GCC := $(TOOLS_DIR)/gcc-2.95.2/gcc ...`, `CC_FLAGS := -mrnames -fno-builtin -fsigned-char -gcoff`, `OPT_FLAGS := -O2`, `SDATA_LIMIT := -G8`, commented-out alternatives gcc 2.95.2 `cc1` and PsyQ 4.6 `CC1PSX.EXE` under wine; no IDO reference; no issues filed. https://github.com/mkst/esa , https://raw.githubusercontent.com/mkst/esa/master/Makefile , https://github.com/mkst/esa/issues . So it is not a precedent for a ucode-family compiler on PS1; its codegen ($v0-first temps, gp-relative `-G8`) is gcc's, unlike ours ($t6-first temps, IDO prologues, no `$gp`).
- CelestialAmber/tokimemo: "WIP decompilation of Tokimeki Memorial: Forever With You (PS1, 1.1)", 4 commits, splat files (`tokimemo.exe.yaml`, `.ld`, `symbol_addrs.tokimemo.txt`); its Makefile is the esa template (gcc 2.95.2, `-O2 -G8`, `-mgpopt`, PsyQ 4.6 `CC1PSX.EXE` commented out), no compiler analysis, nothing about frames or IDO. https://github.com/CelestialAmber/tokimemo , https://raw.githubusercontent.com/CelestialAmber/tokimemo/main/Makefile . Nothing usable for T-3100.

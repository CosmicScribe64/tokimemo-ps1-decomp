## Commands (all through Docker)
`tools/docker.sh` builds and runs the image natively for the Docker host (arm64 on Apple Silicon, amd64 elsewhere; `TOKIMEMO_PLATFORM=linux/amd64` forces the emulated amd64 image, the only one with the old-gcc compilers). Both give identical binaries; see [[toolchain]] ("Native image", T-3310). A clean build takes about a third of the time natively on Apple Silicon.
1. `tools/docker.sh python3 tools/extract_disc.py "<game>.zip" disc` once, to create `disc/`.
2. `tools/docker.sh python3 configure.py` writes `build.ninja` (ninja regenerates it when `configure.py` changes) and `objdiff.json`.
3. `tools/docker.sh ninja` splits, assembles, compiles, links and checks the sha1 of the main exe and of all 26 overlays (default target). `ninja overlays` builds only the overlays, `ninja build/ovl/TT.ok` one overlay.

## Reusing C across identical functions (T-1300)
`tools/docker.sh python3 tools/dupes.py [--apply [--check]] [--unit NAME] [--lenient] [-v]` (tests `tools/test_dupes.py`) needs a built `asm/`. It fingerprints every function of `asm/{nonmatchings,matchings}` (main and the 26 overlays): instruction words with `%hi/%lo`, `jal`/`j` targets and branch-to-symbol offsets masked, register and opcode bits kept; functions with jump tables or data are ignored. Groups with a function already in C and unmatched members are planned: the C is copied, the function renamed, and symbols are mapped by position in the relocation sequence (one-to-one, equal addends; main-exe symbols are identified by address through `config/symbol_addrs*.txt`, so `func_8007ED84` and `bg_read_sub2` are one symbol). Declarations of the target's symbols are copied from the source header closure into the target overlay header (created, with the `#include`, when the overlay has none) or `game.h`/`main_only.h` for main, unless the target already declares them identically. Ambiguous cases are skipped and listed with `-v` (string literals, `static`, unmapped calls, unknown types, a target declaration that differs; `--lenient` accepts the target's own declaration and lets the build judge). `--apply --check` builds each touched object (`build/ovl/NAME.ok`, `build/SLPM_86.053.ok`), and on failure reverts it and retries copy by copy, keeping only the ones that match. Finish with a clean build as the final gate.

### Near duplicates (T-3320)
`tools/docker.sh python3 tools/neardupes.py [--report | --apply [--check]] [--unit NAME] [--func NAME] [--lenient] [-v]` (tests `tools/test_neardupes.py`; run it after `dupes.py`) extends the same idea to functions with equal code shape and other constants. The fingerprint also masks the 16-bit immediate of `addi/addiu/slti/sltiu/andi/ori/xori/lui` (not on `$sp`: frame size and local addresses stay in the shape); load/store offsets, shifts and branch offsets stay, so a group has the same opcodes, registers and relocation positions. A `lui` plus the `ori`/`addiu` completing it count as one 32-bit constant. For an unmatched member without a byte-identical matched twin, `dupes.plan_copy` renames the function and maps symbols and declarations; then each constant that differs between the matched member and the target is substituted by value in the C text. A substitution is made only when it is unambiguous: every instruction carrying the source value maps to the same target value, the value occurs as a C literal (a leading or binary minus counts as its sign; decimal or hex style and digit width are kept) and not more often than there are instructions carrying it (an array index or similar would otherwise change too). Otherwise the function is skipped with a reason (`no C literal` for enums, macros and folded expressions; `maps to different constants`; `N C literals for M instructions`; sign flip in a subtraction; plus the dupes.py reasons). `--report` (the default) prints groups, fillable members and bytes, skip reasons, groups with no matched member (match one and `--apply` fills the rest), functions not fingerprinted (jump tables, string data) and how many more a load/store-offset-masked shape would cover. `--apply --check` writes the C and builds each object like dupes.py. Limits: a differing relocation addend, `x > N` compiled as `slti N+1` (the literal differs by one from the instruction), constants from `sizeof` or enums, and the 1400+ unmatched jump-table and string functions that dupes.py also excludes.

## Pipeline
`splat split config/SLPM_86.053.yaml` -> `asm/` (generated, gitignored) and `build/SLPM_86.053.ld`; each `c` subsegment of the `main` segment is a `src/main/<addr>.c` that splat creates only if missing (`INCLUDE_ASM` per function; edit afterwards, never regenerate) -> asm objects via `mips-linux-gnu-as`; C via `tools/cc.py` with the toolchain `configure.py` assigns per file (`C_FILES` is read from the yaml's `c` subsegments, every file IDO 5.3 unless listed in `C_TOOLCHAIN_OVERRIDES`; IDO 5.3 through asm-processor with the frame-layout emulation pass `tools/frame_pass.py`, see [[toolchain]]; gcc path `cpp | cc1 | maspsx | as` kept for SDK C; stage failures abort, depfile lists the `INCLUDE_ASM` .s files) -> `ld -T build/SLPM_86.053.ld -T build/undefined_syms_auto.txt` -> `objcopy -O binary` (the header section is the first 0x800 bytes, so the output is the complete PS-X EXE) -> `sha1sum -c` against `config/SLPM_86.053.sha1`.

## Frame pass
Every IDO compile (main exe and overlays) goes through `tools/frame_pass.py` via an `as1` shim under `USR_LIB` (details in [[toolchain]]). `configure.py` lists `tools/frame_pass.py` as an implicit input of the C compile rules, so changing it rebuilds all C. `tools/docker.sh python3 tools/test_frame_pass.py` runs its unit tests.

## Overlays
Each overlay in `config/overlays.txt` is its own target (see [[overlays]]): `splat split config/overlays/<NAME>.yaml` -> `asm/ovl/<NAME>/` (gitignored) and `build/ovl/<NAME>.ld` -> one IDO object per `c` subsegment (`src/ovl/<NAME>.c`, or `src/ovl/<NAME>/<addr>.c` per original object after the T-0500 migration, see "Per-object C files") plus the rodata/data asm objects -> `ld` with the splat script and `build/ovl/<NAME>_undefined_{funcs,syms}_auto.txt` -> `objcopy -O binary` -> sha1 against `config/overlays/<NAME>.sha1`, giving `build/ovl/<NAME>.ok`. The 26 `src/ovl/*.c` files are created by splat once (every function `INCLUDE_ASM`) and committed; like the `src/main` files they are never regenerated. `config/overlays/*.yaml`, the sha1 files and `config/overlays.txt` come from `tools/docker.sh python3 tools/gen_overlay_configs.py` (needs `disc/`). Status: all 26 rebuild byte-identical; O.BIN is not built ([[tickets/T-0201-obin-format-and-symbols]]).

## Gotchas found
- gas pads the standard `.text` section of every object to 16 bytes, which shifted everything after a lib object whose size is not a multiple of 16. `tools/asm.py` assembles splat's `.section .text` into the custom section `.text.sdk` (no padding) and renames it to `.text`; the linker script's `SUBALIGN(2)` keeps placement exact (T-0010).
- `configure.py` derives `ASM_FILES` from the `asm` / `rodata` / `data` / `bss` subsegments of `config/SLPM_86.053.yaml`; splitting a segment needs no `configure.py` edit.
- splat rewrites `include/include_asm.h` and the `.inc` macro files on every split, which dropped the IDO guard from T-0013; `generate_asm_macros_files: False` in the yaml stops that.
- splat rewrites `include/include_asm.h`, `macro.inc` and friends on every run, which clobbers the hand-edited IDO guard and breaks the IDO build after the first split. Both the main config and all overlay configs set `generate_asm_macros_files: False`.
- asm-processor rejects a function that is a single 4-byte `nop` ("too short .text block"; the reason for the 1-nop pad problem, solved by the trailing padding pass of T-1310, see [[toolchain]]).
- The linker aligns each section end to 16; the overlay code segment must therefore end on a 16-byte boundary (the generator rounds up) or later symbols shift.
- IDO cannot parse `__asm__`: `include/include_asm.h` skips its macros when `__sgi` is defined, and asm-processor replaces the `INCLUDE_ASM` lines itself, assembling them with GNU as and `include/asmproc_prelude.inc` (label macros without `.ent`/`.end`, plus `gte_macros.inc`). asm-processor runs with `--convert-statics no` because its `.mdebug` static-symbol import crashes on IDO `-EL` objects; C `static` symbols are therefore not visible to `INCLUDE_ASM` code yet.
- `ld_gp_expression` must be a string; `include_macro_inc` is not a 0.50 option.
- Shift-JIS strings (T-0012): `string_encoding`/`data_string_encoding: SHIFT-JIS` makes splat write readable UTF-8 `.asciz "..."` lines (with the raw hex in a comment), and gas would emit UTF-8 bytes (+0xC70 total in the main exe). `tools/asm.py` re-encodes every non-ASCII character of a `.asciz`/`.ascii`/`.string` literal to Shift-JIS octal escapes before assembling, so the bytes match again. The main config and all overlay configs (via `tools/gen_overlay_configs.py`) use SHIFT-JIS now; tests: `tools/docker.sh python3 tools/test_asm.py` (run from `tools/`).
- The link needs `build/undefined_syms_auto.txt` (131 addresses in overlay/heap space, see [[overlays]]).
- Four tiny functions (`func_80066A68`, `func_80066A70`, `func_80066A78`, `func_80066AC0`) were emitted by splat with `jlabel`, which gives harmless `.end without .ent` assembler warnings.
- In a fresh checkout the first `splat split` rewrites the committed `include/include_asm.h` with splat's own version (no `__sgi` guard), and the IDO compile then fails with `cfe: Error: include/include_asm.h, line 27: Syntax Error`. Restore it with `git checkout include/include_asm.h` and rerun `ninja` (T-0014; fix tracked in [[tickets/T-0101-splat-overwrites-include-asm-h]]).
- Generated `asm/` contains game code and must never be committed (gitignored with `build/`, `disc/`).

## Per-object C files (T-0500)
The C files follow the original objects (translation units), so each C object provides its own rodata: jump tables, string literals and constants come out of IDO at their original addresses. Boundaries and evidence: [[source-files]] ("Original objects"); data: `config/objects/<UNIT>.txt` (`tools/object_boundaries.py --write`).

- **Layout.** Overlay: one `c` subsegment `<NAME>/<addr>` per object (`src/ovl/<NAME>/<addr>.c`, asm in `asm/ovl/<NAME>/{non,}matchings/<NAME>/<addr>/`, object `build/ovl/<NAME>/src/ovl/<NAME>/<addr>.o`), one `.rodata` island `<NAME>/<addr>` per object with rodata, `rodata` asm pieces `<NAME>_rodata_<addr>` for chunks no object owns, and one `data` subsegment `<NAME>_data` from the end of the rodata to the end of the file. Main exe: `src/main/<addr>.c` as before (`main/<addr>`), more files, islands `main/<addr>`, pieces `rodata_<addr>`. The header stays one per overlay (`include/ovl/<NAME>.h`).
- **Migration.** `tools/docker.sh python3 tools/split_objects.py [--dry-run] UNIT...` (`UNIT` = overlay name, `main/<addr>` for one main file, `main`, or `--all`; needs a split `asm/` that matches the current yaml, i.e. a finished `ninja`). It cuts the current C files into top-level pieces (INCLUDE_ASM lines, C bodies, `#if` groups, declarations; comments go with the next piece), gives each function to the object holding its address, writes one file per object with the INCLUDE_ASM folders rewritten, copies the top-of-file declarations into the files that use them (stops if two objects use one definition with storage), regenerates the INCLUDE_RODATA lines (below), adds a prototype to the overlay header (main: `include/main_only.h`) for a C function that C code of another object calls without a declaration, writes `config/labels/<UNIT>.txt` and rewrites the yaml. Then `python3 configure.py && ninja`. Re-running it changes nothing; on a tree with new C it re-cuts from the current files (tests: `tools/test_objects.py`).
- **INCLUDE_RODATA lines** are generated, never hand-placed, in island objects: an early (non-table) rodata symbol of the chunk that no function of the object mentions (a string reached only through a `.data` pointer table), or that a C function names as an extern, gets `INCLUDE_RODATA("<asm_path>/data/<name>.rodata", D_X);` in front of the function owning the next symbol (end of file if none). `tools/rodata_pieces.py` writes those pieces.
- **Labels.** splat names a rodata symbol only when something in the same subsegment points at it; strings reached through `.data` pointer tables lost their labels when the overlay blob was cut. `config/labels/<UNIT>.txt` (generated) lists the INCLUDE_RODATA symbols and the yaml's `symbol_addrs_path` reads it, so the labels and the `.word D_X` references in the data come back.
- **Tools.** `tools/srcscan.py` (`c_files()`) reads the C files from the yaml files; `configure.py`, `progress.py`, `queue.py` (J and S no longer block in a file with an island), `dupes.py`, `funcdiff.py`, `m2c.py` (`UNIT:func_X` for addresses several overlays share), `permute.py`, `trailing_pad.py`, `objdiff.json` (one unit per C file) and the CI (unit count from `objdiff.json`) follow. `gen_overlay_configs.py` keeps an existing yaml's subsegments and labels file.
- **Validation.** A trial run of `split_objects.py --all` on a copy of this branch (440 objects, 357 islands; 7 + 637 INCLUDE_RODATA lines in main and overlays) rebuilt 27 of 27 sha1 from a clean `asm/` and was idempotent; RENSYU, OMIMAI, TEL, OLH and `src/main/80062CD0.c` are migrated in the branch itself.
- **asm-processor limit.** A function emits its tables through dummy floats or a dummy switch, which needs enough instructions; `object_boundaries.py` refuses an island when an `INCLUDE_ASM` function is too short (`late_rodata_fits`). None is left: the two cases (`func_80066A2C`, `func_80066A84`) were splat mis-splits whose case blocks had become separate functions, fixed by sizes in `config/symbol_addrs_main.txt`.

## Jump tables: rodata islands (T-1340)
A C `switch` with four or more dense cases makes IDO emit a jump table into the C object's `.rodata`. The splat `rodata` subsegment is one asm blob, so that table would land after it instead of at the original address, and the tables of still-`INCLUDE_ASM` functions are in the blob too. Solution, uniform for the main exe and all overlays (902 jump-table functions exist: 66 in the main exe, 836 in the 25 overlays that have tables; counted from `%lo(jtbl_` in the splat output):

- **Island.** A dot-prefixed `.rodata` subsegment named like a `c` subsegment, e.g. `[0x2110, .rodata, RENSYU]` or `{ start: 0x6F3F0, type: .rodata, name: main/80053650 }`, is a range of rodata that the *C object* provides: splat puts `build/.../<name>.o(.rodata)` there in the linker script and writes the range to `<asm_path>/data/<name>.rodata.s` (never assembled). The ordinary `rodata` subsegments before and after it stay asm blobs (`configure.py` reads the yaml for the asm objects, `overlay_data_files()`, and regenerates `build.ninja` when a yaml changes). `tools/docker.sh python3 tools/rodata_island.py <yaml> <c name> <function...>` cuts the island for the object that holds the tables of the given functions (see below).
- **Hand-over.** After every `splat split` (ninja rule `split`/`osplit`) `tools/rodata_pieces.py <yaml>` appends the island's symbols to the `INCLUDE_ASM` function files `<asm_path>/nonmatchings/<name>/<func>.s` of the first function that mentions them: `.section .rodata` for strings and constants, `.section .late_rodata` for `jtbl_*`. asm-processor then places them like the compiler would (strings in source order, tables after all strings in function order) and splices the real bytes over its dummy data, so a converted function simply stops including its `.s` and the compiler emits its own table at the right position. Symbols no function of the file mentions are written to `<asm_path>/data/<name>.rodata/<symbol>.s` and must be placed by hand with `INCLUDE_RODATA("<asm_path>/data/<name>.rodata", <symbol>);` (the script prints them). `tools/cc.py` lists `INCLUDE_RODATA` files in the depfile like `INCLUDE_ASM` ones. Both scripts: unit tests `tools/test_rodata_tools.py`.
- **Why it is only a chunk.** IDO writes one object's rodata as [strings and constants in source order][all jump tables in function order][zero padding to 16]. That ordering is what asm-processor and the island reproduce, and it holds for exactly one original object. A C file with several objects (every overlay, and the `src/main` files that are unions of originals) has several such chunks, but its object has only one `.rodata`, so **one island per C file**: the chunk of the object that holds the converted functions. The object boundaries are visible in the splat output: a table block ending in zero words (padding up to a 16-byte boundary) is the end of an object (70 such cases over the overlays; tables that follow each other without zero words are in one object). `rodata_island.py` stops at them, refuses functions whose tables are in different objects, and checks 16-aligned start and that the padded end equals the end of the last table block. A boundary without visible padding (object size multiple of 16) makes the island too long; the sha1 then fails and the island must be cut by hand (yaml offsets). To convert tables from a second object of the same file, the file has to be split per object first: done by `tools/split_objects.py` (section "Per-object C files"), which supersedes `rodata_island.py` for migrated units.
- **Limits found.** Float and double constants are late rodata in IDO as well but are not handled (`rodata_pieces.py` treats only `jtbl_*` as late; the sha1 check fails if an island holds some). A string literal first used by a converted function but also used by an `INCLUDE_ASM` one is emitted twice (loud failure: sha1). A C function that names an island symbol as an extern (e.g. `format(D_800AFBF0)` for a string) leaves the symbol without an owner: write the literal in the C instead (`format((u8 *)"bu00:")`, as the original did), or `INCLUDE_RODATA` the piece in the position of the original. `migrate_rodata_to_functions: False` is set in the main and generated overlay configs (splat would otherwise copy the symbols into the function files itself, defining them twice).
- **Check.** `funcdiff.py` shows relocation and label noise for jump-table functions (expected side names `jtbl_*` and `.L*`, built side `.rodata` plus offset); decide with the sha1 line of `ninja`. Matched with it (T-1340): main `func_80053DDC`, `func_8007A254`; overlays RENSYU `func_80133E5C`, ETC `func_8014A2C4`, DATE `func_8013EB1C`, DATE2 `func_80133620`, GYOZI `func_8013AE80`, EVENT `func_8011A874`. The yaml islands of exactly those eight files are committed.

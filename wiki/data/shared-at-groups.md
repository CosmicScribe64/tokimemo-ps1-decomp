# Stores that share one `lui $at` in the original (T-5020)

Data for type recovery. Each row is one group of addresses that the original stores to through a single `lui $at` (a connected component per original object: two addresses are joined when one `lui $at` serves stores to both, inside a basic block). By the measurement in [[matching-notes]] ("Shared constants, shared `lui $at` and loop unrolling"), the original's as1 shares `$at` only for stores through the same symbol, and no address pair is shared in one place and re-emitted in another within an object. So each group is very likely one struct or array in the source of that object (the group shows the stored members only; the object can be larger). Neighbouring addresses in different groups were separate symbols. Same-address repeats (bit-field updates) are left out.

Update (T-9010): IDO 5.3 does reproduce the shared `lui $at` when the symbol is **defined** in the same C file (initialised or static); it re-emits for an `extern`. So each group is one variable of the sharing function's object, and the function matches once that object's C file defines it ([[decompile-workflow]], "Data defined in the C file"; [[matching-notes]], "Shared `lui $at`: data defined in the file"). The old statement here (no sharing even with one symbol) was measured on externs.

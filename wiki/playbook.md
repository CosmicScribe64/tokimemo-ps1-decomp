# Matching playbook

Read this first. It holds the recipes that closed matches; the long pages are reference. The loop: m2c draft -> fix types and control flow (`funcdiff` shows structure rows) -> `viewsweep` -> `autotweak` / `order_search` / `permute` -> `regdiff` for register rows -> `funcdiff --resolve` until `MATCH`, then the full `ninja` sha1. All tools run in Docker:

```
tools/docker.sh python3 tools/funcdiff.py --resolve UNIT:func_XXXXXXXX
tools/docker.sh python3 tools/viewsweep.py UNIT:func_XXXXXXXX            # callee/return-type views, run first
TOKIMEMO_SCRATCH=<scratch> tools/docker.sh python3 tools/regdiff.py UNIT:func_XXXXXXXX   # read FIRST DIVERGENCE only
tools/docker.sh python3 tools/autotweak.py UNIT:func_XXXXXXXX --time 300
tools/docker.sh python3 tools/order_search.py func_XXXXXXXX --unit UNIT -j 8
tools/docker.sh python3 tools/permute.py func_XXXXXXXX --time 120
```

**Verdict rule (T-24700):** `funcdiff --resolve` prints `MATCH` for a function that is still `INCLUDE_ASM` because both sides are the original .s ("compared default build"). That is not a C match. A promotion needs the `compared NON_MATCHING C` version with no diff row (then remove the guard and re-run) or a default build whose body is C; only then does `tools/progress.py` count the function.

Guard rules: readable C that does not match stays under `#ifdef NON_MATCHING` only when it is under about 30 rows, with a ticket id and what is left in the comment; every FAKE comment names the ticket and the reason; no inline asm. If a variant does not compile, `funcdiff` prints no diff lines: check for `MATCH` or `DIFF`, do not count zero rows. References: [[register-cheatsheet]] (symptom table), [[decompile-workflow]] (tools in full), [[notes/functions]] (past notes per function), [[build-step-gaps]] (what the compiler cannot reproduce), [[cloud-matching]] (single-function scratch setup).

Model of the compiler: uopt colours registers (v0, v1, a0-a3, t0-t5, s0-s7 in that order, by priority, then first mention). ugen hands out `t6..t9, t0..t5` as a ring for expression temporaries. as1 deletes redundant ops (`and 0xFF`, `sll/sra` pairs, copies) but those ops still spent ring slots, then schedules delay slots per source line.

**What closed the wave 8-11 matches:** [[notes/wins-2026-10]] lists all 93 (2026-10-22/23, as of commit a018bb0e9; two later matches are listed at its end) with the deciding change, grouped by recipe, and ranks the levers by how often they decided a match: loop shape, which values are locals, access path, types, the unit's data in C, neighbouring globals as one object, ugen_pass state F, never-true arms, source lines. Sections 13 and 14 collect the two families that recurred most.

## 1. Every register one off, instructions equal

**Type of the function and of callees.** Symptom: an `or v0,...` or `li v0` the draft lacks, wrong delay-slot filler, a promoted counter in `$v1` instead of `$v0`. Fix: run `viewsweep`; typical result is `s32 f()` with no `return` (v0 live at exit) or `s32 callee();` as a view in the header guard. It closed 19 of 102 wave-3 blockers; example `s32 func_8013E810();` took RPG_BAT `func_80138324` from 158 to 4 rows (T-24303). Caveat: re-check the callers (full-unit sha1), and check `funcdiff --proto` first to try a prototype without editing.

**Return type changes the delay slot.** Symptom: mode-address `lui` or loads in branch slots where the original has `nop`. Fix: make the shared declaration and definition `s32`, K&R. Caveat: the working explanation is return-register liveness, not an allocator rule; the void control differs.

**An int view of a void callee takes `$v0` away after the call.** Symptom: a range that starts right after a call (a loop pointer in the next preheader) takes `$v0` and the loop-invariant values `$v1`; the original has the reverse. Fix: call the function as an implicit int (try `funcdiff --proto 's32 f(...);'` first). TAIIKU calls Rot_2D as `func_80086204`: 44 rows to 0 in `func_8013E894` (T-25102). More implicit-int closers: GYOZI `func_80138C9C` (debug print `func_800BCDF0`, T-25120), MASTER `func_801326B4` (`func_800847B8`, T-25130), main `func_800455C4` (VSync, T-25123), ETC `func_8013FFAC` (`func_800AE0A0`, `func_8004A1A0`, T-25314). A void library call may need a value-returning prototype too. GEKO `func_80135DC0` calls strcpy as bare statements and never uses the result, but it matches only with the view that returns the destination: with the void prototype, case 0 of its switch puts the `D_80144F14` value in `$v0`, not `$v1` (T-11900). main `func_80055AFC` writes `p = bzero(dst, n);` with a pointer-returning prototype and `p` never read, because the original reads bzero's `$v0` after the call (T-25310, FAKE).

**The reverse, when the callee must stay int:** a callee defined in the same file cannot get a void view (cfe rejects the redeclaration). If the ranges right after an int call skip `$v0` and a void experiment fixes them, end the block after the call with an empty test of its result, `if (f()) { }` (FAKE; uopt drops it). Main `func_80061A3C`, 34 rows to 0 for the copy pointers after `func_8006190C` (T-25119).

**The original passes more arguments than the callee reads.** Symptom: two values used in a loop sit in `$a2`/`$a3` from the loop head (`lui a3; lbu a3`), the draft has them in `$a1`/`$a2` or as a field range plus a local range, and the loop's callee reads only `a0`/`a1`. Fix: pass them as 3rd and 4th arguments, `func_80132D04(0, (s16)(day + i - 1), day, month);`, and keep the callee unprototyped (its K&R definition gives the same bytes). Extra arguments are precoloured and live past the `a0`/`a1` writes, so uopt keeps both values there. Pass locals assigned from the globals: a narrow global passed straight to an unprototyped callee gets its own widening range. GEKO `func_80133024`, 2 rows to 0 (T-25401): the extra arguments are plain C; the reads into the locals in each arm are FAKE. [[register-cheatsheet]] row "argument registers at a call differ from the prototype" is the reverse case.

**`i << 1`, not `i * 2`, when the original recomputes an offset from the counter.** uopt strength-reduces a multiply of the loop counter into a second induction variable and leaves a shift alone (TAIIKU `func_80139AB0` and `func_8013E894`, T-25102).

## 2. A temporary one register too low or too high (ugen ring)

**Ops that as1 deletes still cost a slot.** Symptom: every `t` register one lower than the original from one block on, no instruction missing. Fix: add a no-op that ugen numbers: `idx = sp47 & 0xFF;` on a `u8` out-parameter (main `func_80054884`, 17 rows to 0, T-24214); `((f() == 1) != 0) && ...` on a call test (ETC `func_80140AE4`, 16 rows, T-24207); a third `|=` on a promoted narrow global (MASTER `func_80132444`, T-24208: each narrow `|=` spends two slots, so the count of ORs before the copies sets the numbering). Mark FAKE. Caveat: the right count is found by trying 1, 2, 3; the permuter finds these disc-free. A narrowing cast that as1 drops also spends one: `if ((u8)g->unk_F80 & 0xF)` on a word flag test put the missing slot in the right block (main `func_8006BA40`, 7 rows to 0, T-25008); place it in the first block whose temporaries are off, and remove casts that only moved the numbering later. Wave 8-11: `(u16)`/`(u8)` conversions of the shifted or masked value (not of the parameter, which then loads with `lhu`) in main `func_80046AC8` (T-25124); `(x + 1) & 3` on two-bit fields in NAME_ENT `func_80138C1C` (T-25149); `(u8)` on a call result in KANGEI `func_801327DC` (T-25139); `(u8)r * 8` in main `func_80049A40` (T-25115); `j = unk_03A & 0xFF;` in ETC `func_8013FFAC` (T-25314). The reverse: m2c's `& 0xFF` on a u8 product spends slots the original did not. Drop it when the original keeps the product in its own register (`mflo s0` against the draft's `mflo t4`): TACO `func_8013FBF0`, 80 to 51 rows (T-25141).

**Split a sum to fix ugen's free-list order.** uopt reassociates a one-statement sum, so its temporaries are freed in another order than the original's. Separate statements keep the order: `level = f9; level += (A > 0) * 2; level += (B > 0) * 2;` (ENDING `func_801330E4`, T-25145, found with a FIFO model of the free list on the `cc -S` listing). In the same function `(x > 0) * 2` gives the original's in-place `sltiu; xori`, where `(x == 0 ^ 1) * 2` uses two registers. A dead store to an operand after its first use keeps a later copy on its own line in the same way (`q = 0;` after the first store, main `func_80047560`, T-25116, FAKE).

**One extra temporary can be corrected by a full ring wrap.** In TACO `func_801511C0`, removing an empty argument test restores the correct early home store but spends one extra temporary on a home reload that as1 deletes. `i = (u32)arg0 < 0` supplies a late zero; ten alternating +i/OR-i operations in an existing scalar initializer consume nine intermediate slots and are deleted by as1, completing the ten-slot ring. The final OR preserves the original OR-move opcode. This is an explicit source-local FAKE, semantically +0/OR0 with no overflow, extra frame slot or runtime instruction. Prove the intermediate count and final literal bytes; do not blindly add a long identity chain. See [[tickets/T-25047-taco-home-store]].

**Parameter width.** `t7` vs `t8` throughout: try `u16`/`s16`/`s32` for the parameter, or a K&R `u8` parameter for a selector (main `func_8007B144`, T-17012 family). Also split `v = x >> 3; v += (x >> 3) * 80 / 48;` when an s16 narrowing must take the temporary (T-19008).

**Colour bytes.** `p->r = (c >> 16) & 0xFF;` keeps the shift in a ugen temporary (the `and` is dropped before `sb`); plain shifts or `u8` locals become uopt ranges (T-16220). Put the three stores of one vertex on one source line (T-17203, DATE `func_8014EF1C`, 143 rows to 0).

## 3. Value in a register vs reloaded; promoted ranges

**Narrow global promoted by a byte view.** Symptom: the original has `andi v0,..; or a0,v0,zero; jal; sb v0` where the draft forwards `sb v1`. Fix: store through a byte view and re-read the plain field, `((u8 *)&D_800E6280)[0x1118] = slot; f(D_800E6280.unk_1118)`; a second view re-store in a later arm may be needed (ETC `func_80144DF0`, 47 to 0 rows, T-24209). The reverse also works: plain stores, view re-reads (T-24206). Caveat: view store plus view re-read puts the value in `$a0` with no `move`.

**Original reloads, draft CSEs.** Fix: read the second use through an address view, `*(u8 *)((u8 *)&D_800E6280 + 0x3E)`, or through a `GameState *gs` pointer (uopt treats a pointer store as a possible alias). In main `func_8006D7EC` the original mixes `gs->` and absolute accesses; the `gs->` form for record stores recomputes `sll; addu` per statement as the original does (T-23003).

**The access path decides reloads, CSE and ranges.** A read through a pointer local (`GameState *g = &D_800E6280;`, a work pointer `w = &D_800F53A0;`) is an indirect load (ILOD) to uopt; a direct read is a plain load. 32 of the 93 wave 8-11 matches used this:
- *Reloads.* uopt treats a store through the pointer as a possible alias, so the next read reloads: VALEN `func_80132834` (336 to 120 rows, T-25117), NAME_ENT `func_80138C1C` (T-25149), OPTION `func_801326BC` (the `% 4` index is recomputed after each palette store, T-11900), main `func_80065B0C` (the index through `g` is killed by the x store, T-25108).
- *One range.* A read through a pointer is not copy-propagated: main `func_80055AFC` keeps `arg0 = g->unk_1117 & 1` as a copy, so the bank base is one range (T-25310). A typed pointer to one hot field, `GsWord *fc = &D_800E6280.unk_1104;` with `fc->u` at every read, makes the field one range and stops a rival global taking its register (ETC `func_80144224`, T-25146; cast forms of the pointer do not do it).
- *Two expressions.* `g->` next to an absolute read of the same field gives two expressions with the same absolute `lui/lbu`: main `func_80067F04` (`gs->unk_03F` in the first test of each pair, 519 rows to 16, T-25103), GEKO `func_80135DC0` (absolute reads for the call arguments, 84 to 24, T-11900), TEL `func_8013D88C` (the F64 flag word: `FLAGS_F64(g)` in the page-one and month-ladder tests, `FLAGS_F64(&D_800E6280)` in the other flag tests, T-25133). All three splits are FAKE.
- *Index like the sibling.* `base->unk_1328[index]` instead of a stepped pointer (main `palette_load_vram`, 554 rows to 22, T-25134); in a switch, index the pool in every statement (section 8).
A function-wide pointer local is plain C. A second path to the same field that is kept only for allocation (an absolute read next to `g->`, a byte view next to the field) is a FAKE and is marked in the sources (the three splits above, SHOUGATU `func_801350F8`).

A later call argument can keep an earlier selector promoted across several tests. SHOUGATU E6E4 needed both an exact byte view at the second club test and at the later status-call argument: the first restored a reload, the second removed the remaining `a0` range and matched the temporary sequence. Integer debug return fixed the preceding flag register. See [[tickets/T-25038-shougatu-selection-loop]]; these are marked FAKEs, and individual removal controls establish their roles.

**Delete a redundant local.** If regdiff lists a shift or sum as its own range next to your local, remove the local and repeat the expression (TAIIKU `func_8013B200`, 79 to 43 rows, T-19008). If a global is written back at every loop latch, drop the local array base and index the global (main `func_8006612C`, T-17011).

**Global as the variable.** A local held in the wrong register and stored to a global in each branch: assign the global itself and read it back; uopt promotes it and colours as the original (T-10860 family).

**A loop store that may alias stops a hoist.** Symptom: the original computes a value before a loop guard, or reloads a global in every pass, and the draft computes it after the guard in the preheader, or loads it once: uopt's copy propagation or loop-invariant motion moved it. Fix: let a store in the loop possibly alias an operand. Read the operand as a member of the record the loop stores into: the random word as `state->unk_10F8` (VALEN `func_80132834`, 23 rows left after it, T-25117), or `D_800F53A0.unk_10C8 + i` instead of `D_800F6468 * 1 + i` (GYOZI `func_801412A4`, 276 rows to 19, T-25151). Or view the loop's array and its count as one record: `#define CL (*(CandList *)D_80147224)` with `CL.values[i] = ...` and `CL.count` (GYOZI `func_80138C9C`, 75 rows to 12, FAKE, T-25120). An indexed member read of one struct ends the promoted ranges of its sibling members in the same way (RPG_BAT `func_80144C84`, the `RpgBattleView` override, FAKE, T-25138). VALEN `func_80132834` and GYOZI `func_80138C9C` are the same scene in two overlays: when one matches, try its spelling on the other.

**A load sunk to its first use: a volatile member of the global's own type.** uopt moves `v = h >> 12` down to its first use, so the original's load order is lost, and an empty `if (v) {}` that pins it adds a label that clears ugen's register cache. Read the global through a `volatile u16 vh` member added to its union (`D_800E6280.unk_0F4.vh`, FAKE): uopt keeps a volatile read in place and nothing else changes. A volatile pointer cast in the C file builds a base-relative load instead. GEKO `func_80133C50`, 13 rows to 0 (T-11910).

**Promoted global left uncoloured.** Symptom: the original keeps every read of a byte global in one argument register (`lui a3; lbu a3`) and the draft loads some into ugen temporaries. Fix: read it through `GameState *g = &D_800E6280;` and add one more read in an empty test, `if (g->unk_041) {}`; the extra use raises the range's priority so all pieces take one colour (ETC `func_80146D4C`, 82 to 28 rows, found by the permuter, T-25007). FAKE.

A `u16` global read only through shifts (`h >> 12`) keeps its CVT at every read (cvt_pass), so uopt sees no plain use and every load is a ugen temporary. The original has `lui v1; lhu v1` at every read, after calls too. Two empty truth tests `if (D_800E6280.unk_0F4.h) {}` anywhere in the function make it one `$v1` range; one test is not enough (KANGEI `func_801327DC`, 175 rows to 0 with the other fixes, T-25139). FAKE.

**Split a range with an empty test.** `if (x) {}` after an assignment splits or reorders live ranges and adds no code (GEKO `func_801358CC`, found by autotweak, T-24302). Unassigned locals grow the frame by 8. Always FAKE.

## 4. Operand order of compares and sums

`bne` operands reversed, registers right: read the selector through a u32/s32 local (GYOZI `func_8014206C`, T-20005 note), or the aggregate (T-16930), or wrap the left operand `w * 1 != x->width` (`| 0`, `^ 0`, `<< 0` also work; `+ 0` does not) (main `strNext`, T-17014). When t0..t3 are permuted inside one expression and nothing else differs, read the ucode entering uopt: cfe puts the heavier operand of `+`/`*` first (an indexed array read is heavier than a local or scalar, a `u32` conversion adds weight), and ugen takes each temporary from its FIFO list when it emits the instruction. A local copy of the array element (`x = A[i + 1]; ... v / 32 + -x / 2`) evens the weights so source order holds; otherwise `(D | 0) * k` or `a - (0 - A[i])` (FAKE) (main `func_80062948`, T-25119). For sums, spelling decides: `(idx + D_X)->f` gives index first, `(D_X + idx)->f` base first (TACO `func_801557E8`, T-16564); in RPG_BAT `func_80138324` the last 4 rows were the global first in two sums (T-24303). Wave 8-11 sum orders: the table term first, `D_801492B8[k] + (x >> 3) * 6` (TAIIKU `func_80137C44`, T-25106); comparisons `unk_06 + unk_02` and assignments `unk_02 + unk_06` (VALEN `func_80132834`, T-25117); the shift written before the array read (TACO `func_8013FBF0`, 51 to 4 rows, T-25141); `unk_03F + 1 == month + 12` (main `func_80067F04`, T-25103). A sweep of all 24 orders of a four-term sum found the one that uopt reassociates into the original's load order (ETC `func_801328A4`, 16 to 2 rows, T-25121). Compare orders: only an `s16` selector local gives `beq a2,v0` (GYOZI `func_801412A4`, T-25151); ugen emits a register variable before a loaded expression, so compare against the promoted global, not a local copy, when the original has the load first (NAME_ENT `func_80138C1C`, ETC `func_8013F054`).

**Address sums (T-25114).** cfe orders the two `addu` operands of an address value: `&p[i]`, `p + i` and `i + p` are index first; a subscript read or store (`IXA`), `p += i` and an integer sum in source order are base first; uopt keeps the order. (A field access through the sum keeps the source order, `(D_X + idx)->f`, T-16564.) One range with two orders, base first in one arm and index first after the join, needs integer address sums, `(s32)&D + i * 4` in the arm and `i * 4 + (s32)&D` at the join (FAKE): pointer forms split it into two ranges. RPG_BAT `func_8015528C`, 4 lines to 0.

**A byte-global compare built constant-first by cvt_pass.** Symptom: `bne a1,t0` built, `bne t0,a1` expected, and uopt's own output is load-first. tools/cvt_pass.py `_constant_first` swaps a compare of an unsigned global whose widening it stripped, and its `rewritten` set covers the whole unit, so a sibling function's loads of the global count too. Escapes: read the byte at another location, `((u8 *)&D_8013CAA4)[-4]` for `D_8013CAA0` (ENDING `func_801387B0`, T-25148, FAKE); or keep the CVT (store the global through a view at entry, an ISTR that leaves it out of the entry set) and write `r * 1 == G` with `r = 1;` (GYOZI `func_80138C9C`, T-25120, FAKE). ENDING `func_801387B0` also needed four spellings of one repeated `(flag & 1) == 1` (plain, `(x ^ 0) == 1`, `x * 1 == 1`, `(x << 0) == 1`) so that uopt shares only the AND (T-25148, FAKE; [[register-cheatsheet]] T-24023 section).

**A pointer compare against a fresh `lui/addiu` of an array base is an index test (T-25502).** Symptom: `bne aN,tM` of a CSE'd slot address against the base built fresh at the compare, and every source pointer compare reverses the operands or puts the base in a register. Write the test on the index, `if (x == 0)`: when `&arr[x]` was formed in an earlier block and the raw index is not used after the test, uopt's test replacement (LFTR) rewrites it as `&arr[x] == arr`, and the base never becomes a register candidate. TAIIKU `func_80137784` (open since T-24521; T-25201 and T-25309 had concluded it needed second symbol names) matched this way; the deciding change is plain C (the three T-25106 FAKEs of the earlier passes stay); TAIIKU `func_8013F3A4` (section 8) is the same rewrite. Conditions: the [[register-cheatsheet]] row that starts "`bne aN,tM` of a CSE'd slot address".

**An indirect load on the other side (T-25401).** cfe puts an operand that contains an ILOD first in a sum, whatever the source order; with ILODs on both sides the right operand goes first. A register local is a plain LOD, so `(x << 23) >> 27` from a local always comes after a table entry. `tbl[i] + ((*&x << 23) >> 27)` (FAKE) makes the local an ILOD for cfe only: uopt reads it from the register again (GEKO `func_80132B24`, 18 rows to 0; the merged source uses the equivalent `(date = date) << 23 >> 27` from T-11910).

## 5. Store order, delay slots and as1 line grouping

as1 schedules per source line. Put initial assignments on one line (`n = 0; b = 0; p = A; r = B;`) to keep ugen's order (main `func_80055A38`, T-17007); the loop init on the `do` line, the body on the `for` line (T-11650); two constant stores on one line in the constant numbering order (T-16554). Write `c++` before the record stores if the original loads early (T-23003). One statement per line is the default; the exceptions are the FAKE layout recipes above, marked in the source. `order_search` permutes lines but never joins them. Wave 8-11 line joins (FAKE layout unless the line is a macro): the pre-loop store, the loop-variable init and the `for` header on one line (RPG_BAT `func_8014BFE4`, T-25144); the count-loop body on the `for` line (GYOZI `func_801412A4`, T-25151); `x2 = ...; h = ...; y2 = ...;` on one line when `cc -S` shows uopt emitting `h`'s subexpression under the x2 line (ETC `func_8013D570`, T-25113); the row-10 stores of a table (TEL `func_8013D88C`, T-25133); one line per switch case (main `srn_tpage_show`, `mod_set`, T-25104); three record stores and `n++` as one macro line (main `func_80067F04`, T-25103).

**Packet builders: write the libgpu macros first.** When the constants and stores of a POLY/SPRT builder spell PsyQ macros (`setXYWH`, `setUVWH`, `setRGB0..3`, `setUV4`, `setXY4`), write each macro as one comma statement in the macro's field order before any register work. as1 then groups the stores per macro line, and the field order also settles ties between constants coloured by first mention. main `srn_tpage_show` (592 rows to 0 with two other changes, T-25104), main `func_8004A414` (142 to 16, T-25122), main `_sprite_set_light_effect1` (setRGB1/setRGB2, 4 to 0, T-25115), TACO `func_80139424` (setUVWH, T-25112), TACO `func_8013FBF0` (the UV stores, T-25141). FAKE layout: a hand expansion of the macro, marked as in the other files that do it.

Hoists from another block (as1's global filler, [[as1-scheduler-rule]]): as1 moves the head `lui` of a dominated block (for example the out-of-range default of a switch) into a stall. Fix: declare the globals of the instructions that must stay `volatile` in the header; a volatile global's `lui` and load are never moved and the code is otherwise unchanged (VALEN `func_80134030`, GYOZI `func_80139E4C`, T-24900; FAKE). Caveat: not for a global the function reads twice in a way uopt can merge (it then loads it once, VALEN `func_80132D0C`); two reads in separate conditional blocks are fine (GYOZI `func_8013907C`, T-25120). Not for weight-limited picks, which the file's own data table fixed instead (GEKO `func_80136C20`, below), or same-block order (KANGEI `func_8013852C`). The reverse also works: a non-volatile view `*(u8 *)&G` of a volatile header global in one test lets as1 hoist that `lui` (VALEN `func_80133088`, 26 to 14 rows, T-25117, FAKE).

**Two stores to one data symbol get two `lui $at`.** as1 shares one `lui $at` across offsets only for a symbol defined in the C of the unit, inside one 16-byte-aligned chunk of the section. If the symbol is still an `INCLUDE_RODATA` piece, replace that line with its C definition (TAIIKU `func_80139AB0`, `D_801499B0`, 5 rows to 0, T-25102).

**A load that the original keeps on one side of a store to another global: the two may be one symbol.** as1 keeps a load and a store in order only when both use one symbol; with two symbols its list scheduler moves the stores (long `$at` chain) above the load. Symptom: order-only rows where a promoted global's `lui/lw` sits after neighbouring stores in the draft and before them in the original. Check whether both addresses fall in one known block and reach them through it: TAIIKU `func_8013DDB8` reads `D_80122EC4` as offset 0xF4 of the `D_80122DD0` block and `D_8012080E`/`D_801207EB` as fields of actor record 102 of `D_8011ECD0` (16 rows to 0, T-25102). ## 7. Stack frame size and offsets

Every declared scalar owns a 4-byte slot, promoted or not; arrays sit lowest; scalars declared before an array go above it; spilled locals take slots top-down in declaration order. Fixes: declare the real scalars before tables (GEKO `func_80132B24`, only three scalars, T-24302); add `s32 pad[n]` or `u8 pad[4]` and mark FAKE (ETC `func_80144DF0` needed `pad[3]`, T-24209; TAIIKU `func_8014280C`, T-16554); remove expression-temp locals (`tbl`, `rec`) in big functions; `A[f()] = v` reserves a spare slot, so use `idx = f(); A[idx] = v;` (T-16554). Overlay and main frames are handled by `frame_pass`; write C for a normal frame. `order_search` with `/* ORDER */` around declarations finds the declaration order (T-16230). Turn a pad slot into the real local the source likely had when ring numbers also differ. Homes below every slot the declared locals can reach are uopt spill homes (`rstr`/`rlod` in uopt output): strength-reduced products of a loop counter (`o * step`, `o * 4`) and copies get them in creation order. Remove the declared `rot`/`q` locals and write the index loop instead of padding (TACO `func_8013DEE4`, `&pt[j * 2 + o]`, 69 rows to 0, T-25110). A small compare-chain `switch` also takes a cfe temporary slot after the declared locals. Wave 8-11: a frame change was part of 40 of the 93 matches. Delete a local whose spill sits below the declared homes and repeat the expression (`(y + 1) % 3` for `next_row`, ETC `func_801328A4`, T-25121); a hoisted expression can own a spill home (`limit` written as `arg1 - 3`, main `func_80056BA8`, T-25118). uopt hands out spill homes in bit order, first fit (`spilltemps`): to move one, change its item's bit, by copy propagation (`half = 0x80; ... j * half * 2 - half`, TACO `func_8013EAA4`, T-25201) or by writing the expression inline (texture u/v in the call, main `func_80046AC8`, T-25124).

**Two frame words too many, homes right: drop the negated locals.** If a value kept in its own web (`v0`) is negated into `nx = -x` and passed to two calls, uopt spills nx to a new home below the declared locals, so a declared `nx`/`ny` slot is never used but still costs its word. Declare only x and y and write `-x` in both calls: uopt keeps `-x` in a temporary across the first call (one store, one reload) and the frame shrinks by the unused slots. With plain reads (x folded) `-x` twice is spilled and negated again instead. RPG_BAT `func_80154DD8`, frame 0x60 to 0x58 (T-25308).

## 10. Block copies

For copy mismatches, distinguish direction state from temporary-register choices. The historical direction mismatch is handled by the enabled T-24092 `ugen_pass.py`; see [[build-step-gaps]]. **End pointer one ring slot high (source + 3, the original source + 2).** In our pipeline the `ugen_pass.py` sentinel sets how many scratch registers ugen burns before the end pointer: state B burns two, state F burns one, for aligned copies too. ## 12. Byte views and bit-fields

Flag byte `|=`: use a bit-field store `((Bits *)&x)->f = 1;` when one temporary is missing (T-11650). The shape gives it away: a bit-field store loads the byte into another register than its `lui` (`lui t9; lbu t0,(t9)`), and on a promoted byte it adds `move t,v0; ori; andi v0` before the store. A plain `|=` gives `lui t; lbu t,(t)` with no copy (main `func_8006A044`, 174 rows to 86, then 0 with a dead read for the colour order and an implicit-int return, T-25103). A 3-bit field decremented in a byte is `f -= 1` on a bit-field typedef, not shifts (T-23003, 561 to 482 rows). Repeated `|=` through a byte view spends ring slots (T-24302: one OR gives `t4`, two give `t8`, three `t7`). A u16 flag read after a `+=`: test through an `s16` view `((*(s16 *)&D) & 0xFF00)`, not a cast (main `func_8007A50C`, T-17012). Flag tests that the original compiles as `sll 29; bltz` where the draft has `andi 4; bnez` are bit-field reads (`unk_0C.f.b2`, KANGEI `func_801327DC`, T-25139).

## 14. Loop shape: index loops, counters, `for`

Loop shape decided 18 of the 93 wave 8-11 matches and helped in 30. m2c prints loops after uopt's strength reduction (pointer walks, cursors, counters stepped by the stride); the original was written in the form that uopt reduces.

- **The index form, not the walk.** Signs: the preheader sets saved registers in register order (uopt's strength-reduction setup); spills sit below every declared home (uopt induction temporaries, section 7); a `.noalias` is missing (a declared pointer walk has none); the base and the loop bound share one register (a pointer loop lets uopt CSE them, an index loop gets its own LFTR bound). Write `p[i]`, `base + i * k`, `x[i << 1]` or the full coordinate expression from the counter. ETC `func_8013D570` (aligned cost 604 to 20, T-25113), ETC `func_8013F054` (T-25113), TEL `func_8013D88C` (T-25133), main `make_color_bar` (every store from the pair index `k` with a constant row offset, `p[k]`, `p[k + 16]` to `p[k + 112]`, T-25140), NAME_ENT `func_80138C1C` (T-25149), TAIIKU `func_8013E1FC` (T-25102), TACO `func_8013DEE4` (T-25110), OPTION `func_801326BC` (T-11900). - **Counter ownership.** Which source counter runs which loop decides unrolling and colours. With one counter shared by every loop, IDO unrolls only the last loop of the function (main `func_8005557C`, T-25105); a counter assigned again later keeps a loop rolled, and a fresh counter unrolls a small loop (TAIIKU `func_80139AB0`). - **Index tests that became pointer compares:** section 4 (T-25502).

## Known compiler limits

Do not spend a session on these without a new idea; leave a guard with the ticket id and what remains. Details and the census in [[build-step-gaps]].
- Historical ugen block-copy direction mismatch (T-19001, T-22014): addressed by the enabled `tools/ugen_pass.py` in [[tickets/T-24092-ugen-block-copy-state-pass]]. Reproduce remaining failures with the current pipeline; 32-byte unrolled-copy register choices are a separate question.

### Before proposing a compiler or build-step change

The compiler has been compared and traced in depth. Start from these results; do not re-run them.

- Which compiler: release 3.18, the IDO 5.2 generation, from the linker stamps in O.BIN ([[original-compiler]]).
- IDO 5.2 against 5.3: byte-identical on 2,564 matched functions and on all 46 blocked cases tested (T-3110, [[ido-52-evaluation]]). Switching compilers gains nothing. `tools/ido_eval.py` repeats the comparison for one function if a new case needs it.
- IDO 4.1's back end: its ugen gives the +16 frames natively but changes 1,355 matched functions; its as1 changes 1 (T-20700).
- uopt register allocation: eight uniform allocator rules all broke matched code, the best 661 functions; only 2 true tie-breaks exist (T-9800, [[uopt-register-allocation]]). The compiler levers of T-25013 to T-25015 were all rejected.
- What did work: differences in the ucode the original front end produced, which no stock IDO reproduces: `tools/cvt_pass.py` (T-1321, T-5010, T-24929), `-cckr` (T-7000), plus the frame pass (T-0016) and `tools/ugen_pass.py` (T-24092). A new compiler difference, if there is one, most likely belongs in the ucode before uopt (an extension of `cvt_pass.py`), not in uopt or as1.
- Any such change must meet CODING_STANDARDS.md 7a and leave all 27 checksums unchanged. [[build-step-gaps]] lists the gaps still open.

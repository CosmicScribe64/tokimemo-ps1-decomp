# as1 global delay-slot filler

How IDO 5.3's as1 fills a load-delay or branch-delay stall with an instruction from another basic block, measured with a traced as1, and the source levers that change its choice. Related: [[build-step-gaps]] (as1 order row), [[playbook]] section 5, [[ending-allocator-trace]] (the T-24047 path-barrier finding), [[matching-notes]] T-24211 and T-24212.

## Global delay-slot filler (T-24900)

### Tracing recipe

Everything runs in Docker; all files stay under the ignored `build/`.
The scripts are in `drafts/T-24900-as1/` (copy them to `build/as1tr/`; the traced as1 binary goes to `build/as1tr/bin/as1-x2`): `cap.py`/`xtr.sh` capture and trace one unit, `fn.py` cuts one function out of the trace, `toys.sh` runs toy files, `vr.py`/`vu.py` score variants of one function or of a whole unit, `mkvol.py` writes a header copy with chosen globals volatile.

1. Capture as1's input. A scratch shim replaces `tools/frame_pass.py` as the `as1` shim of `tools/cc.py` (`cc.SHIMS["as1"]`): it applies `frame_pass.transform` to the binasm file, saves it as `in.G` with a copy of the `-t` symbol file (`in.T`), and runs the real as1. The unit is preprocessed with `funcdiff_verify.preprocess_draft` (NON_MATCHING on or off) and compiled with `cc.main`.
2. Replay `in.G`/`in.T` through a print-only build of the recompiled as1: `/private/tmp/t24047-uopt/variants/as1-trace.c` (generated by `drafts/T-24047/as1_trace.py`, which adds `XBBSCAN`, `XBBDETAIL`, `XBBRESULT` and `XBBPATHBARRIER` lines) plus one more `fprintf` that prints the relocation kind of each candidate. Build: `gcc -std=c11 -O1 -fno-strict-aliasing -I. as1-x2.c libc_impl_53.o version_info.o -lm` in the arm64 image (the two objects are in `/private/tmp/t24047-uopt/recomp/build/5.3/`). Options: the build's own (`-elf -G 0 -p0 -EL -g0 -O2 in.G -o x.o -t x.T`) plus `-R -xbbdbg 8`. The output object is byte-identical to the build's (checked on VALEN 80133C70.c).
3. Run it under `stdbuf -o0` so the stock trace lines (`current bb`, `MOVETO`, `MOVEFROM`, weights, dominators) and the added lines stay in order. A function's lines are the ones whose `lineno`/`Line` fall inside its body in the preprocessed unit.

### The rule

as1 first schedules each block on its own. It then numbers the blocks, gives each a weight, and visits every block that still has a stall (an unfilled load delay or branch slot) in ascending (weight, number) order. For a visited block D:

1. **Candidate blocks.** It walks the blocks that come after D in (weight, number) order and stops for good at the first block whose weight is at least D's weight + 6. A block is tried only if D dominates it (`XBBSCAN` lines with no detail are blocks that D does not dominate). So the blocks of equal weight (D's control-equivalent joins and tails) are tried first, then the next level (+3), and never the level after that. There is also a candidate-count cutoff: the outer region admits11 dominated blocks; a natural-loop region admits101. Failed instruction searches consume this budget too (T-25056 below).
2. **Weights.** Weight = 1 + 3 per controlling branch for plain `if` and `switch` code: in a switch head of weight 1 the default and dispatch blocks are 4 and the cases 7; a function body after an early `return` starts at 4. A predecessor that also leaves the current region adds 1 instead of 3 (OMIMAI `func_80134384` has weights 2 and 5).
3. **Block numbers are not layout order.** The out-of-range default of a jump-table switch is numbered right after the range check and before the dispatch, even when its code is laid out after all cases. With equal weights (4 and 4) the default is therefore tried before the dispatch.
4. **Candidate instructions.** Inside a candidate block the instructions are tried in order. An instruction is a candidate only if its `volatile` mark is clear (the `sched` pair printed as `0/1`; a volatile access and its `lui` print `1/1`), it is movable (loads, stores, calls and branches are not), it does not conflict with an earlier instruction of the same block that stayed, and its relocation kind is 0 to 3 (`%hi` of a global is 2).
5. **Path test.** Every block on the paths from D to the candidate block (D included, the candidate block excluded) must not end in an indirect jump (`XBBPATHBARRIER` on the dispatch block, flag bit 6), and the register the instruction writes must be dead on every edge that leaves those paths. This is why a join after a switch never gives D anything (the dispatch is on the path) and why `lui $at` loses (D uses `$at`).
6. **Acceptance.** The move is kept only if the two blocks together get faster and, unless they are control-equivalent, D gets no slower. After a move the scan continues in the same block from the next instruction, then in the next blocks, until D has no stall left.
7. **What stays in the slot.** If nothing passes, the stall stays a `nop`. In a switch head the dispatch block's `sll` is the usual filler of the range-check slot; it cannot fill the selector's load delay because it reads the loaded selector.

Source lines play no part in these choices; they only order the per-block schedule.

8. **Indirect jumps reach every address-taken label (T-25150).** as1's CFG builder (`func_41dc10`) gives each block that ends in an indirect jump other than `jr ra` an edge to every block whose label is address-taken in the file: all jump-table entries of all switches, and every function that a `.word` in the same file's data names. A switch dispatch in a function named by a C-defined table therefore has a back edge to the function entry; the loop changes the weights (dispatch 2, the +1 rule) and the scan order of the switch head. KANGEI `func_80134724` matched only once its object's table `D_80139B30` was defined in C (data island). A file whose original `.data` names its own functions must define that data in C before the scheduling of its switches can match. The loop also changes which blocks a stall can take from. In EN_NICHI `func_80136DEC` (T-25201) the back edge comes from a jump-table `jr` inside case 3 of a compare-chain switch. The loop region (processed before the outer region) holds the compares and the case-3 head but not the heads of cases 1 and 2. Those heads drop out of the compares' candidate lists, and each compare slot takes the next compare's constant, as in the original.

### Levers that work

**`volatile` on the globals whose `lui` must stay.** It sets the volatile mark on the access and on its `lui`, so the global mover never takes them, and for a plain declared global it changes nothing else (no extra instruction, same local order). The declaration has to be volatile; a `*(volatile s32 *)&X` cast makes IDO build the address with `addiu` (27 to 48 rows).

Before (VALEN `func_80134030`, 6 rows): `lbu t0; lui t1; sltiu; beqz; lui t2; sll t0 ...` with `extern s32 D_80134690;`.
After (match): `extern volatile s32 D_80134690;` and the same for `D_801346C4`, `D_801346F8` (VALEN.h) gives `lbu t0; nop; sltiu; beqz; sll t0`. The same three-line change matches GYOZI `func_80139E4C` (GYOZI.h). Declaring all 39 table words volatile also matches both units; only the three default-arm words are volatile in the tree, marked FAKE (the real declaration is unknown).

Use it when the trace shows the wrong instruction is a `lui` of a global that is only read in the function (or whose other readers still match), and check every unit that includes the header.

A global read twice is fine when the original also loads it twice, each read in its own conditional block (GYOZI `func_8013907C`, two `D_80147240 == 1` tests, T-25120). Another reader in the same unit whose per-block order changed went back to its original order with a non-volatile view at one read, `*(u8 *)&D_80147240` (FAKE).

### Levers that do not work

- **Order and shape of the switch** (default first, in the middle, reversed cases, `int` selector, `goto out` instead of `break`, default after the switch): the block numbers and weights come from the control flow graph, which these forms do not change.
- **Data placement** (defined, static, bss, array element, `const`): the relocation kind stays 2 or 3, still movable.
- **Volatile when the global is read more than once.** VALEN `func_80132D0C` (T-24212): the wrong pick is bb 9's `lui v0` of the `mode` reload. A volatile `D_80134544` pins it but uopt then loads it once instead of twice (13 rows); a volatile read in the first `if` only changes the allocation (190 rows).
- **Weight problems.** GEKO `func_80136C20` (T-24203): the selector `lui` sits in a block of weight 7 and the target block has weight 1, so the scan stops before it. The original must have had the switch head one level lighter; volatile on the two flags makes it worse (6 to 12 rows).
- **Same-block order.** KANGEI `func_8013852C` (T-24202): `lui $at` before an `addu` is the per-block scheduler, not the global mover; volatile on the stored globals changes nothing (2 rows).

### Open

- What makes the weight of a block add 1 instead of 3: answered 2026-10-21 (T-25013, from the pinned recomp as1 source, confirmed on a traced GEKO `func_80136C20` run). A predecessor contributes pred + 1 exactly when at least one of its successors is outside the current region bitset (the test is func_428758 in the recomp source, walking the predecessor's successor list); pred + 3 when every successor stays inside; pred - 3 when the current block dominates the predecessor (a back edge). Predecessors outside the region are skipped. For GEKO `func_80136C20` the original's switch-head CFG must have earned one such +1; that is a source-shape question for the GEKO ticket, not an as1 build rule.
- A form that pins one of two reloads of the same global for VALEN `func_80132D0C`.

### Separate preload blocks and late folding (T-25037)

BUNKA_SD func_80139290 now reproduces the local year-load order and global constant fillers through C. An early empty comparison on the already-loaded frame stages the constant in one uopt block; a separate `if ((u32)g->unk_03E < 0) {}` stages the year preload in the next. The unsigned-false test disappears after uopt has placed the preload. Case0x49 requires the constant0x60 test and year test before its store0. Case0x66 requires the frame==1 test before store1 and the year test afterward; placing the store first introduces an extra selector recomputation. Entry reloads were observed in register order, while edge reloads preserve their own linked-list order. This supplies the upstream separation missing from T-25023. These are marked FAKE source forms, not a compiler change. Both guarded and promoted C have literal1516-byte proof; see [[tickets/T-25037-bunka-upstream-emission]] and drafts/T-25037/README.md.

### Promoted store emission changes the local tie (T-25041)

KANGEI func_8013852C closes through an empty read of its just-stored global. `if (D_80139ADC) {}` makes uopt promote that value and emit `rstr` on the next line, separating its address preparation from the sum. Both old and new local traces show aftercycles4 and besttime15 for lui versus16 for addu at time16, yet the new trace chooses addu. Readiness alone therefore does not explain the old tie; line/emission context matters. Removing the redundant `(u16)(s16)` conversions from the u8 year compensates for the promoted result's conversion and preserves t6. The resulting default C passes literal180-byte proof. See [[tickets/T-25041-kangei-preload-schedule]] and drafts/T-25041/README.md. This supersedes the readiness-only interpretation in T-24901/T-25018 without changing the old experiment results.

### Candidate-count cutoff in a large function (T-25056)

ENDING func_8013A2E8's first flag block exhausts the outer-region search budget
before reaching either flag arm. In reconstructed as1 `func_42aa0c`, labels
`L42acdc`/`L42ad20`, the threshold is10 for the outer region and100 when
`region+4` holds a natural-loop header. The old count is compared with `>` before
increment, admitting11 or101 dominated candidate blocks. This counts blocks,
not instructions, and failed motion attempts consume the count.

The current guarded source's block10 examines eleven equal-weight joins and
stops on block320. Raising only the general threshold to100 in a scratch
diagnostic reaches flag block11 at count15 and first call arm58 at16; both
delay slots then match and funcdiff proves4648 literal linked bytes equal.
The diagnostic's default output equals stock. This explains the historical
T-23002 deletion threshold, but is not a production match or an accepted
compiler rule. Source-only controls and exact reproduction are tracked by
[[tickets/T-25056-ending-scheduler]] and `drafts/T-25056/`.

Cached original IDO5.2 has the same100/10 region-header selection. Replaying
the same captured ENDING input gives all1164 stock5.3 candidate instructions
unchanged. A simple5.2-to5.3 historical budget change is therefore excluded;
the scratch raised-budget result still lacks an original-compiler rationale.

Resolved (T-25127): the original's source gave the loop region. The object's scene table
D_8013CB74 names func_8013A2E8; defined in C (data island), it gives the function's jump-table
`jr` a back edge to the entry (rule 8, T-25150) and the unchanged guard body matches. Before
chasing this cutoff in another function, check whether its object's `.data` names it.

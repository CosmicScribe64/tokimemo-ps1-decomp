# Small overlay group: entry and primary rules

Source-backed port specification for KANGEI, DATE2, EN_NICHI, OLH, OMIMAI, RENSYU and VALEN. This page's proposal tables and counts describe their original handoff; current C names and applied status follow the source tree and applied ledgers, and not every candidate row is claimed applied. KANGEI `camp_` names are isolated in `config/renames/proposals/o-small-hypotheses.tsv`; corresponding technical identifiers are present in the applied ledger, but overlay/story grouping remains unconfirmed. No game text is reproduced.

## Loader entry map

The main overlay loader table in `wiki/spec/m-flow.md` supplies the mode, disc LBA and entry PC. The C body at an entry is called once per frame; a file's address 0x80132000 is not necessarily its only entry.

| Overlay | Mode -> entry PC | Per-frame entry behavior (source) |
|---|---|---|
| KANGEI | 0x5F -> 0x80132FF8; 0x60 -> 0x80132000 | 0x5F entry `func_80132FF8` switches on mode_stage (0..0x1F scene phases) and draws the HUD; it is not the 22-entry mode_step callback table. For 0x60, `func_80132000` calls the scene dispatcher at mode_stage 0 and resets to title otherwise; its scene callback dispatcher is `func_80132214` (22 entries indexed by mode_step). The loader table and ADR mark camp interpretation as HYPOTHESIS. |
| DATE2 | 0x58 -> 0x80132214; 0x5C -> 0x80137F64 | `func_80132214` dispatches mode_stage 0..4, then draws parameter/background for stage 0 steps <0x13, otherwise shared frame/HUD. The second entry has a karaoke-return flow in `80137D50.c`. |
| EN_NICHI | 0x82 -> 0x80132000 | Initializes stall-game setup; later steps use the common scene state. `func_80132278` restores caller mode/stage/step. |
| OLH | 0x3A -> 0x80132000 | `func_80132000` dispatches help page groups by mode_stage and checks Start to return to command screen. |
| OMIMAI | 0x61 -> 0x80133120; 0x62 -> 0x80132000 | 0x61's `func_80133120` dispatches mode_step through a 26-entry table only at stage 0, otherwise resets to title. 0x62's `func_80132000` dispatches stage 0 through a 25-entry mode_step table, stage 1 through the separate 12-entry table at `func_80132D44`, and resets to title for all other stages. |
| RENSYU | 0x73 -> 0x80132040 | Callback table selected by mode_stage; actual practice flow is in the callback bodies, with the intro sequence at `func_801320E0`. |
| VALEN | 0x54 -> 0x80132274 | Stage 0..3 dispatch; other values reset to title. The loader mode is Valentine's Day. ADR still requires confirmation before treating additional White Day content as part of this overlay. |

## Per-overlay state and outcome rules

### KANGEI (camp context is a hypothesis)

The complete KANGEI source census is 152 definitions across eight current C files, and each has a unique body-backed function row in the separate hypotheses table. Source paths are current semantic filenames. Every proposed `camp_` function name is marked HYPOTHESIS; do not treat the overlay's story, season, or scene identity as confirmed. These rows are excluded from the ordinary apply table until that grouping is confirmed. The observed loader entries stay distinct: mode 0x5F enters `func_80132FF8`, a mode_stage dispatcher, while mode 0x60 enters `func_80132000`, whose mode_stage-zero path calls `func_80132214`, a separate 22-entry mode_step dispatcher. Their indices must not be merged.

The day-event path is connected through the observed state transitions: `func_801335F0` initializes UI/audio and increments the club-indexed player mode counter; `func_801335A0` increments the day-event index, advances date/calendar display and mode_stage; `func_80133A14` runs the timed event update; `func_80133A54` chooses an audio command from the control bits, adds two practice points to the club bucket selected by `player_flags`, calls `parameter_up_down` with the active day's girl and scene, and advances after its repeated-call counter reaches the threshold. `func_801338EC` waits for audio readiness, clears two screen rectangles and calls `day_event_next(1)`. `func_80132E40`/`func_80132E74` and `func_80132090` install scene and dialogue pointer arrays. These bodies establish calendar, practice-point and day-event effects; they do not establish that the overlay is a camp event.

The scene flow has separate dispatch tables: `func_80133C10` dispatches 15 stage callbacks, `func_801341E8` dispatches 30 callbacks, and `func_80135678` dispatches an 80-entry paired-actor table. `func_80134120` routes a met current girl to the 30-step flow, an unmet non-YUMI girl before year 0x61 to another callback path, and otherwise advances mode_stage. Candidate setup uses player club bits, girl club bits and met flags; the year>=0x60 selector-10 branch compares Shiori's affection+tokimeki with girl 10's total. The specific story interpretation remains unresolved.

Birthday and girl-script paths are body-covered through their table producers and consumers. `func_80138078` tests girl 0's birthday first when D_80139AC4 is clear, then the player's birthday; otherwise it advances mode_stage and clears D_80139AC0. `func_80138158` dispatches through separate 67- and 68-entry callback tables based on the club-bit comparison. Script pointer builders fill two 3-by-13 tables; binding helpers select text/command/voice rows; `func_80139540` copies the script segment indexed by current girl, year offset and selector. Response handling in `func_80138470` subtracts one affection and adds five syoushin for nonzero response, clamps, and skips 0x38 steps; zero increments the script selector. Shiori status gates and date/player-birthday branches alter mode_step and script offsets. `func_80138F88` selects a met girl with minimum low-seven-bit status, breaking ties by affection-plus-yuukou; a status below two enters that girl's scene, otherwise it takes a fallback UI path. Event-log numeric codes and narrative meanings are unresolved.

Paired-actor and scene-picture/effect bodies are also covered. `func_80135838` applies a random admission check plus date-girl validity, met status and birthday exclusions before initializing the scene; this is a separate special path, not proof of a particular story label. Resource binders load actor data for YUMI/AYAKO, while their enter/exit helpers configure actor records and audio. Scene-picture helpers bind still/animation pointers, dispatch 40- and 24-entry callback tables, load result resources, render talk lines, build transition primitives, animate fades and update/recycle actor and particle records. `func_8013614C` applies the observed result effects: result zero subtracts ten tokimeki from a valid met date girl; result one adds ten stress; both then clamp. `func_801362BC` only latches `D_80122CDC` into the selected result index after audio command 0x500; it is not the current-girl selection routine. `func_80137638` gates on the selected club field being below three. No inference is made about the prompt or narrative behind these result categories.

Definition coverage is complete, while semantics still unresolved are specific: (1) KANGEI's narrative/seasonal identity and all `camp_` names; (2) meanings of event-log codes and raw selector/result bytes; (3) prompt/content meaning for the birthday, paired-actor, and scene-picture categories; (4) whether the practice-point threshold gate is eligibility, progress, or another condition; and (5) intended C return types where the source deliberately leaves an integer result implicit. Keep these as hypotheses or raw operations. Essential literals are listed in the separate exact-site inventory and are not const rename rows.

### DATE2 (amusement/karaoke overlay)

`func_80132214` routes mode_stage 0..4 to five phase functions. `func_801381A4` sets mode to DATE, stage 1, step 0x11 to return to the caller's date path. It is a concrete interface contract; loader mode 0x5C's story label as karaoke is also supported by `wiki/spec/o-date.md`, which identifies the DATE caller as its karaoke-place third-visit branch.

The callback dispatcher `func_80132DE0` uses a 58-entry table. A separate mode-step dispatcher `func_801326F0` uses the 31-entry table, while the birthday stage has its own 44-entry table via `func_80136660`. The birthday flow at mode_stage 4 has a distinct pointer setup and an eight-entry mode_step dispatcher at `func_80136FC4`; its caller gates set mode_stage 4. The karaoke return scene uses a separate 13-entry dispatcher at `func_80138048`. Keep these dispatch families distinct. Date2 installs its stage-0 scene pointers at entry and several talk wrappers in `80132000.c` bind different text/voice pointer triplets before calling `talk_run`, with response-dependent pointer selection only in `func_801324A8`.

Birthday stage gates are exact: `func_801366E8` sends Shiori's low-status player birthday to stage 4 and marks day-event bit 4; `func_80136794` does the same for current-girl low status, restoring date_girl as current_girl and clearing the prior bit-8 marker. When the matching birthday occurs without the low-status branch, each marks bit 8 and advances. These are entry conditions for the special birthday branch and not eligibility for the overall DATE2 overlay.

At `func_80136BA4`, branch order matters: Shiori's affection (`girls[0]`) < 10 increments `D_8013A428` by 2 and selects SHIORI; else current-girl yuukou < 10 increments that selector by 2; else Shiori's syoushin (`girls[0]`) >= 0x33 selects SHIORI; else if current girl's syoushin < 0x33, Shiori's tokimeki >= 0x32 increments selector by 1 and selects SHIORI, or current-girl tokimeki >= 0x32 increments selector by 1; if neither tokimeki threshold is met it increments selector by 4 and calls `mode_step_next()` twice. A final common `mode_step_next()` follows. No `else` fallback occurs when current girl's syoushin >= 0x33. This is scene-selection logic, not a scoring result.

The separate karaoke return flow has a 23-entry `mode_step` table at `func_801375D4`. `func_8013775C` applies the explicit nonzero-response penalty (affection -1, syoushin +5 and a 0xD step skip), while zero increments the talk group. `func_8013780C` maps current-girl low-seven-bit status to talk groups 6, 8, 0xA or 0xC. `func_80137948` sets day-event bit 4 and mode_stage 4 only when player birthday matches and Shiori's low-seven-bit status is below 2. `func_80137B94` is another response transition with the same 0/1/default parameter deltas as the earlier result path. The karaoke minigame result updater `func_80138BEC` distinguishes automatic completion at CD position 0x79 from manual pad input: automatic awards tokimeki +2/affection +1, manual gives affection +1 and updates a selector from status (YUMI sets selector 2). The four karaoke threshold/display helpers are now body-covered separately: they scan 30, 51, 39 or 81 threshold entries and display the indexed text at exact counter values. Their text remains in game data, and these results do not establish every interaction condition.

`func_801330D4` sums scene counters 1..0x24 (then subtracts counter 0x1A) for met girls 1..9 and selects the lowest total; it temporarily logs Shiori and the selected date_girl before binding dialogue. The counter semantics remain raw. `func_80133720` sets one selector bit in `D_8013A4C4` for a nonzero response. The values in `D_8013A430`/`D_8013A438` receive explicit status-based +0xA increments; their display meaning is not confirmed. Keep the 58-, 31-, 44-, 23-, 8- and 13-entry callback families separate. Another inspected result body (`func_80136860` in `80132DE0.c`) applies a response code: it counts bits 0..2 of `D_8013A4C4`; 0 adds Shiori (`girls[0]`) affection 12 and current date girl's syoushin 7; 1 adds Shiori affection 3 and girl's syoushin 2; 2 adds current date girl's affection 3 and Shiori syoushin 2; 3 adds current date girl's affection 12 and Shiori syoushin 7. Then it clamps parameters and advances the day event. Exact choice prompts remain in game data and are not repeated here.

### EN_NICHI (festival stalls)

Entry `func_80132000` selects different mode-stage paths for year 0x5F and later years. The first-year dispatcher `func_801320C0` handles stages 0..5, with stage 5 restoring saved mode/stage/step; stage 3 runs the gameplay frame update. Later years use the stage callback table dispatched by `func_80136B10`. For the first-year flow, `func_80132D44` selects four substates; the cursor moves by 2/3 units per frame and is clamped to screen bounds. Holding Circle for four frames records a target and increases the score by 2 plus each target’s encoded value (capped at 0x64); release resolves the ten target flags and updates score/good/bad counters. The exact scoring presentation remains stored in game data. The initial and exit transitions ramp 64 actor brightness entries and screen clear color in fixed steps. Main mode 0x82 enters this flow; the caller in DATE is the shrine-festival path and saves mode/stage/resume step before launch (`wiki/spec/o-date.md`). `func_80132278` clears cursor/upper actors and restores saved mode, stage and step. The later-year setup `func_80136DEC` prepares 22 actor records and, after its audio sequence, resets five target slots before starting the game. `func_80137C58` moves five targets and records a matched callback ID into `D_80139C4C` or 0xFF, and animates hit/finished slots. `func_80138CCC` populates display frames from met girls 0..10 plus eligible girls 11/12; this list controls presentation frames and is not evidence of reward eligibility. `func_80137FEC` first rejects targets using twelve vertical limit checks, then searches twelve actor records in reverse order; each record’s code indexes the separate 33-slot `D_80139D1C` callback table. The 33 callback slots are recovered from `asm/ovl/EN_NICHI/data/EN_NICHI/80136B10.data.s`: slots 0–18 use the fourteen hit-test bodies with repeated entries, and slots 19–32 all point to `func_80138C34`. Thus the callback mapping is known, including duplicates; the 14 C bodies have individual rows. `func_80137E2C` only draws the progress meter. Stall play writes five codes into `D_80139C4C`. In `func_8013735C`, step 0 records up to five Circle selections and their selected values; step 1 compacts non-0xFF codes for display; step 2 reveals each result after at least 0x2E VBLNK ticks. If all five codes are 0x1F it selects mode_step 5, and if all five are 0x20 it selects step 6; those paths play separate audio sequences and return to step 3. Step 4 classifies the result: all five equal 0x10 with Yuina, or all five equal current_girl+0x14 for another girl, yields result 3; otherwise all five below 0x21 yields 1; remaining cases yield 4. Then it restores saved mode/stage/step. The exact meaning of these result codes comes from the caller in DATE, whose rewards are recorded in `wiki/spec/o-date.md` section 7. The result summary routine `func_801362A4` rolls and displays two counters but contains no girl-parameter writes.

### OLH (help)

### OMIMAI (sick visit)

The remaining support functions either bind per-girl dialogue, mark event bits/logs, gate scene progress or configure rendering; no affection/tokimeki/stress/syoushin writes occur in the inspected overlay.

The mode-0x61 dispatcher `func_80133120` uses a separate 26-entry callback table at stage 0; it resets to title at other stages. `func_801337EC` loads the girl from the active day-event record and binds her talk tables. `func_8013388C` selects talk group/variant from girl, last-command low nibble, player club, status and year gates; the conditional random branches vary table choice, and this body does not alter parameters. `func_80134030` skips one or two dialogue steps for particular Megumi/Yuko group conditions; `func_80134384` selects a background based on command/month/club, and `func_80134628` picks a portrait for command 4 from girl/club tables (or reads uniform bustup otherwise). At 0x62, `func_80132000` uses a 25-callback table (`func_801322E4`) at stage 0, a separate 12-callback table (`func_80132D44`) at stage 1, and resets to title for other stages. ### RENSYU (practice match)

## Tables and interfaces

- Main loader contracts are mode + entry address, not implied from folder names. For example DATE2 has two modes and two different entry PCs; OMIMAI has a scene entry plus a common entry; KANGEI has two modes and two PCs.
- KANGEI and RENSYU use callback tables. Their selectors (`mode_step` or `mode_stage`) are exact integer indices; invalid states may dispatch reset callbacks or reset to title, so a port should retain these guards.
- DATE2 returns to DATE using a specific mode/stage/step triple. EN_NICHI returns by restoring its saved caller triple. OLH returns to MODE_COMMAND_SCREEN. OMIMAI and RENSYU complete through `day_event_next(1)` on the observed terminal callbacks.
- Existing tables and global names stay unchanged in this draft; names are proposed separately. Do not commit copyrighted game data.

# BUNKA_SD stage shows and SHUGAKU school trip

This is a body-backed port specification for the two overlays. The definition census and proposal rows describe that analysis pass. Current names and paths follow applied ledgers and source; proposal rows absent from those ledgers remain candidates. Prefixes are recorded in `wiki/phase2-naming.md`: BUNKA_SD `stage_show_`; SHUGAKU `trip_`. O.BIN names remain unchanged. Narrative and outcome semantics remain hypotheses unless the C bodies directly establish them.

## BUNKA_SD: stage-show state flow

`func_801322EC` is the per-frame input wrapper. While `mode_step` is 5..14, held Circle triggers the scene handler and marks ten display actors (records 96–105) with state `0x82`; otherwise it writes state `1`. Held Cross in steps 5..13 issues audio commands and sets step 13. Then the wrapper calls `func_80132428` (source `literature_speech_contest.c`). This proves input gating, but not the game's intent for Circle or Cross.

`func_80132428` dispatches mode steps 0–15 and increments `mode_step_timer` every frame. Step 0 starts scene initialization; 1 waits at least `0x1F` timer ticks; 2 waits for audio-bank and CD sector loading; 3 selects a script; 4 initializes actors and speed; 5/14 run fades; 6 and 12 perform frame-dependent handlers; 7/9/11 run specialized scene helpers; 8/10 dispatch helper durations 15/30; 13 resets actors and advances; 15 evaluates a completion predicate. Any other step resets to title. Source: `literature_speech_contest.c`.

At step 3, `func_80132148` switches on `D_80122EAC` (0..4). Selector 0 chooses script pointer `D_8013B74C`; selectors 1–4 choose paired pointers and set `current_girl` respectively to SOTOI, SHIORI, MIO, MIHARU; those arms also configure audio requests. The function always advances the mode step. The selector's actual show/story identity is not established by the code alone.

Three scene wrappers have related structures: A `func_8013376C`, B `func_80136BFC`, C `func_80137D6C`. They route script/event execution through the corresponding interpreter `func_80133D54`, `func_801373D0`, `func_8013842C`; scene A includes mode steps 4–11, 15–18, 20–36. Script data is indexed from scene-specific event-list/text tables. The interpreter checks the current frame against each `BsdEvent.unk_00`; `0x0FFFFFFF` terminates a list. Command low byte `0xFE` calls the display operation with hide parameters; other values are image IDs. Bits 16–23 select the actor slot and bits 28–31 gate text startup. It advances event/frame cursors and can advance the outer step when the list completes. Sources: `drama_first_year_show.c`, `drama_final_year_show.c`, `drama_second_year_show.c`; shared type evidence in `wiki/families/bunka-sd-family-results.md`.

The scene loaders initialize display actors 96 onward, load palettes and texture pages, and bind pointer tables for the scene pictures. The type-family page establishes these are picture-set pointers and BsdEvent lists. Exact image-to-actor meaning, script identities and any reward interpretation remain unproven. The full BUNKA_SD C census contains no affection/tokimeki/syoushin/player-parameter writes.

The scene-A/B/C dispatchers have separate step maps and separate event-list pointers. Scene A's step handler spans 0..40, scene B's 0..38, and scene C's 0..47; each has explicit audio transitions, timed waits and a reset-to-title default. Circle and Cross handling is gated by each scene's step range and Circle runs the scene dispatcher in the same frame. The event interpreters for B and C share A's event format but use their own frame, list and pointer globals. Step helpers around these dispatchers perform the common actor-brightness ramp (byte increases by 2 up to 0x80 or decreases by 2 to zero), actor/palette/texture-page setup, and post-scene display/audio reset. These are body-observed rendering and flow rules; the displayed strings and picture identities stay in game data and are not copied into this spec.

The complete 98-definition BUNKA_SD census also covers the remaining show callbacks and presentation helpers. `club_year_show_dispatch.c` maps mode_stage to distinct club/year stages and calls one of the 3 first-year, 3 second-year, 3 final-year drama/science/computer/brass show wrappers; `GAME_MODE_CULTURE_FESTIVAL_A/B` and saved caller stage/step are set from the observed selector. The three science-club year flows each have separate sector loaders, input wrappers, mode_step dispatchers, audio/frame timers and actor/palette/texture setup. Brass-band flow additionally switches among three year-specific audio ranges and year-specific CD-tick duration/animation values; its animation selector also depends on three flags. Computer-show flow has a selector-dependent five-actor setup and audio schedule. The second- and final-year drama flows have separate callback maps and separate BsdEvent interpreters; the interpreters process frame-indexed entries, actor slot/image commands, string/audio markers and the `0x0FFFFFFF` list terminator. No affection, tokimeki, syoushin or player-parameter writes occur in the full BUNKA_SD C census. It is therefore a display/event-flow overlay at the source level; image, script, and reward meanings remain unproven.

## SHUGAKU: school-trip state and outcome evidence

`func_80132274` copies callback table `D_8013B094` and invokes the callback selected by `mode_step`. The broader trip has multiple scene families: `func_80132364` sets one set of current pointers and runs `talk_run`; `func_801326F8` switches to another pointer triplet; `func_8013282C` selects text/table pointers by `current_girl`. The callback lists are shared types documented in `wiki/families/shugaku-family-results.md`.

`func_8013282C` maps girls to text/table pointer triplets, calls `talk_names_set(current_girl)`, and selects a year value using `year - 0x5F` when month >= 4, else `year - 0x60`. For NOZOMI only, status `(get_g_zyotai_s(NOZOMI) & 0x7F) < 2` substitutes another pointer triplet. This is body evidence for route-specific dialogue selection, not proof of the narrative content or route rules that produced the current girl/status.

`func_801337FC` is a second low-status candidate scan: among ten birthday-flagged girls it selects minimum low-seven-bit status, breaking ties by tokimeki+yuukou. If girl 4 has status below 2 while saved stage is 5 and scene flag 0x20 is set, it sets day-event bit 8; otherwise a candidate below status 2 is selected only when bit 8 is clear. No candidate binds the default pointer set and skips 0x20 steps. It logs an event code based on saved game mode or location selector, whose narrative meaning is not inferred. `func_8013243C` gates a birthday scene: if the player's current month/day does not match `player_birthday`, it advances the step and returns. On the birthday, it scans ten girls whose `D_800CA2B0[i]` flag is nonzero, choosing the lowest low-seven-bit status; equal status breaks by greater sum of tokimeki and yuukou. If the chosen girl's status is below 2 and the girl index is 0, it selects mode step `0x32`; otherwise it advances normally. The status and array meaning are only described by direct uses here; exact event meaning remains unverified.

`func_80132C64` branches on `D_80122CDC`: nonzero subtracts one affection and adds five syoushin for `current_girl`, clamps parameters, and adds `0x1B` to mode_step; zero increments `D_8013B084` and advances the step. `func_80132D14` adds 2/4/6 to that dialogue/script index for current-girl status values 2/3/other when status >=2, otherwise no offset; it then advances. These are explicit state/flow effects, but the response/status meanings are not proven.

`func_801330E8` is a direct response-stat transition indexed by `D_80122CDC`: choice 0 adds tokimeki +3, affection +2, syoushin -15; choice 1 adds tokimeki +2, affection +1, syoushin -10; every other value adds affection +1 and syoushin +10. It calls `check_para_limit()` and advances the step. `func_80133348` has special saved-stage/current-girl/status branches into mode stages 8, 0xB, 0xA; exact story/result labels for those branches remain HYPOTHESIS. `func_80132BCC` restores saved stage/step unless saved mode stage equals 6, which instead dispatches through `func_8013ABAC`; `func_80132C1C` adds six to mode_step in that saved-stage-6 case.

Additional scene routes have been inspected: `func_80133F6C` sends Shiori birthday to saved-stage 6 and the player birthday to stage 7, both retaining current girl as date_girl; `func_80134C98` does the analogous route while saving the return stage/step as 5/0. `func_80139118` is a separate low-status candidate scan over ten flagged girls: it selects the minimum low-seven-bit status with tokimeki+yuukou tie-break when status <2, otherwise updates a counter and skips the scene path. `func_8013AAEC` maps a three-value location selector to the corresponding place label and adjusts the day counter from two result flags. These details establish control-flow/state use, not the narrative prompt or meaning of the counters.

Other direct school-trip stat transitions in the audited bodies: `func_801350F4` applies tokimeki +5 and affection +2 only when `D_80122CDC` is zero; nonzero adds 0x1D to mode_step and increments `D_800CA2DC`. `func_8013A648` applies tokimeki +5 for nonzero response, adjusts `D_800CA2DC` from the response code and may replace current_girl with YOSHIO or 0xFF under `D_800CA2EC`. `func_80135DB8` applies tokimeki +1/affection +2 when `D_8013C2EC` is zero; otherwise affection +1, increments a counter by 2, and adds 0xB to mode_step. `func_80134658` applies tokimeki +1/affection +2 after scene setup. `func_80134070` applies affection +2, issues audio and restores the saved stage/step. `func_8013ABAC` advances the calendar after audio readiness; `D_800CA2EC` selects between girl 10 affection +1 and current-girl tokimeki/affection +1 before completing the day event. These operations are proven; the prompt/story identity of the associated response paths is not inferred.

Remaining SHUGAKU bodies now include every destination, actor and talk helper. `func_80137490` is the 12-way mode_stage/frame dispatcher; its scene-stage functions each have separate callback tables and rendering contracts. The departure/destination-selection flow initializes eligible-met flags for girls 0..9 (clears slot 10), chooses among three destination selectors and corresponding backgrounds/labels, validates resource pointer headers before decode, and drives a destination-specific actor slide/load sequence. The sightseeing companion selector in `func_80139118` scans ten enabled candidates, ranks by low-seven-bit status then tokimeki+yuukou, selects only a candidate below status two, and otherwise updates the raw counters, skips steps and writes current_girl `0xFF`. `func_80139740` and `func_801398E8` set up a YOSHIO dialogue route under the observed status/response branches. The name YOSHIO here follows the explicit GIRL_YOSHIO symbol; any route narrative remains unconfirmed.

Destination outings use a 68-entry callback table. Its dispatch substitutes `normal_date_three_select` for `normal_date_two_select` when `D_800CA2EC` is nonzero; destination selector and text-index values choose scene labels, backgrounds, counters and actor state. The direct response effects are: `func_801392B4` subtracts tokimeki one and affection two for nonzero response; `func_8013A648` adds tokimeki five for nonzero response while updating destination counters; `func_801350F4` adds tokimeki five/affection two only for response zero; `func_80135DB8` adds tokimeki one/affection two when its scene flag is clear and otherwise adds affection one plus a counter/step change; `func_80134658` adds tokimeki one/affection two during corridor setup; `func_80134070` adds affection two and restores the saved trip stage/step. `func_8013ABAC` waits for audio load, advances calendar day and either adds affection one to girl 10 or tokimeki/affection one to current_girl according to `D_800CA2EC`, clamps, then calls `day_event_next(1)`. These effects are exact source observations; response choices and counter semantics are not labeled beyond their code values.

The remaining scene families are also inspected: Ayako's 44-entry callback flow sets current girl/status selectors, logs event 2/0x1A, gates one branch on liberal-arts parameter `>=0x78`, and sends exact Shiori/player birthdays to stages six/seven. Yukari's 38-entry callback flow sets hotel-corridor title/picture resources and includes the explicit tokimeki +1/affection +2 setup. Yuina's 74-entry mode_step flow handles actor fade/display and can save caller mode/stage with step 0x38 before starting RPG battle; its response/effect callbacks apply the deltas listed above. The school-trip callback tables are read through their producers, dispatchers and selected consumers. Exact prose, image identity, location semantics beyond the literal labels, and the meaning of opaque counters/event-log codes remain unresolved. One stack-byte passed by `func_80134824` is read uninitialized; its intended argument meaning cannot be recovered from C.

## Tables and identifiers

SHUGAKU has three sets of 13-word location pointers and three callback families; the established family page notes that many apparent 12-byte arrays are unrelated scalars and should not be merged into guessed structs. BUNKA_SD uses three event-list pointer arrays of 29, 12, and 31 entries, plus per-script text data. Existing raw symbol spellings are preserved in this analysis. No game text is reproduced.
